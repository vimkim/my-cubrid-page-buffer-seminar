01 · The comparison rule

Start with two protections

Replacement protection prevents a referenced frame from being reused for another logical page. Content protection prevents incompatible access to the current page bytes. Every engine needs both responsibilities; none of the nearest Interfaces is a complete one-to-one equivalent.

CUBRID

pgbuf_fix() → BCB fcnt + thread holder + requested latch → pgbuf_unfix()

PostgreSQL

Pin → private/shared refcount → separate content lock → independent unlock and unpin

MySQL / InnoDB

buf_page_get_gen(..., mtr) → atomic buf_fix_count + S/SX/X memo entry → memo unlatches, then unfixes

CUBRID couples fix, latch, and thread ownership. PostgreSQL separates pin from content lock. InnoDB separates the low-level states but reunites their lifetime in an MTR memo.

03 · The first performance bet

Measure per-thread holder lookup before changing replacement

Verified mechanism: pgbuf_find_thrd_holder() walks the current thread's singly linked held-BCB list until it finds the target. It is called on normal latch acquisition, lock-free READ hits, unfix, dirty validation, and other ownership checks. The lock-free READ path then performs a shared CAS on the BCB fcnt, even when the same thread already holds that BCB.

Inference: when a worker holds many distinct pages at once or repeatedly fixes an already-held hot page, linear holder discovery and shared cache-line traffic may become a CPU bottleneck. PostgreSQL's small private-refcount array plus overflow hash, and its local-only repeated-pin increment, show that the same safety responsibilities can be placed at a cheaper seam. They do not prove CUBRID will be faster after copying that design.

RankHypothesisWhy this order
1Add traversal-depth and cycle measurements around holder lookup; benchmark held-set sizes 1, 4, 16, and 64.Observation only; it identifies whether the linear search is material before redesign.
2Prototype a bounded per-thread lookup accelerator or hash for larger held sets.It preserves today's global fcnt semantics and limits the proof surface.
3If shared CAS dominates nested re-fixes, prototype first/last-holder aggregation so inner nesting stays local.Higher potential, but promotion, waiter fairness, final-unfix wakeup, and victim eligibility currently depend on exact fcnt semantics.
Do not begin with an LRU rewrite. Existing runtime evidence did not force real eviction, and replacement policy has a much larger correctness and workload-sensitivity surface. Profile the ownership hot path first.
04 · Falsifiable experiment

Separate list cost from shared-atomic cost

  1. Use a release build and a resident working set. Exclude storage I/O from the measured interval.
  2. Hold H distinct pages while repeatedly fixing/unfixing one target; sweep H across 1, 4, 16, and 64.
  3. Run one thread, then several threads sharing the target BCB. Record holder nodes inspected, CAS attempts/retries, cycles per pair, and throughput.
  4. Compare four shapes: non-nested/private page, nested/private page, non-nested/shared page, nested/shared page.
  5. Reject the lookup hypothesis if cost is flat with H. Reject the aggregation hypothesis if shared contention does not grow or nested re-fix is negligible in representative callers.

A source-shaped opportunity becomes a performance finding only after the workload makes its cost visible.
