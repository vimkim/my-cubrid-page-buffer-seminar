세션 3 · Daemon과 페이지 교체

페이지는 저장된 데이터 한 덩어리이고, 프레임은 페이지 하나를 담는 메모리 자리입니다. 이런 자리들을 모은 것이 버퍼 풀입니다. 이 세션에서 다루는 CUBRID 데몬(Daemon)은 요청 스레드와 별도로 백그라운드 작업을 하는 서버 스레드입니다.

스캔은 많은 페이지를 차례로 읽는 작업입니다. 자주 읽는 페이지와 큰 스캔이 같은 풀을 사용합니다. 이제 요청 스레드는 메모리에 없는 페이지를 읽으려 하지만 모든 프레임에는 다른 페이지가 들어 있습니다.

후보 페이지 하나는 지금 아무도 사용하지 않지만 변경된 내용이 저장소 쪽에 아직 기록되지 않았습니다. 이런 미완료 변경이 있는 상태를 dirty라고 부릅니다. 그 프레임을 새 페이지에 쓰기 전에 누가 무엇을 끝내고 다시 확인해야 할까요?
