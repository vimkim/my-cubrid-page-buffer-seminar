LECTURE 12A / Replacement

Dormant AOUT admission history

AOUT retains ghost admission metadata in the source, while pinned parameter tuning disables its operation.

Ghost metadataNo frameAdmission onlyForced off
01 · Short answer

AOUT is disabled in the pinned server path

The data structures remain in source, but startup forces data_aout_ratio = 0.0. Initialization allocates no ghost nodes, and add/lookup helpers return immediately. Active replacement is the INVALID/VOID/private/shared three-zone LRU path from Lecture 12.

AOUT is retained, disabled admission-history code. It neither stores page bytes nor chooses a victim in the pinned build.

02 · One ghost entry

A VPID and former LRU index are enough to remember a past eviction

{ VPID, former lru_idx, prev, next }

An entry contains no BCB, frame, latch, fix count, dirty generation, or page copy. The real BCB/frame pair may already represent another page. One global FIFO, free-node list, VPID hash, and Aout_mutex manage the records.

A = min(floor(N × data_aout_ratio), 32,768)
hash tables = max(floor(A / 1,000), 1)

With the pinned default ratio zero, A = 0. If enabled, the FIFO would recycle its oldest bottom entry when full.

03 · Retained design

A ghost hit would change first placement after reload

Reload contextRetained placement branch
Enabled private-LRU assignment; same-private ghost hitCurrent private LRU1 top
Enabled private-LRU assignment; AOUT missCurrent private LRU2 middle
Enabled private-LRU assignment; different former LRUShared LRU2 middle
No enabled private-LRU assignmentShared LRU2 middle

This is admission ranking after load. It does not select the old victim, prove ownership, or authorize reuse. AOUT-off removes the ghost hit/miss subdivision, not the two current paths: an enabled assignment reaches private LRU1 top and no enabled assignment reaches shared LRU2 middle.

04 · Evidence boundary

Reviving AOUT requires a new engineering review

The forced-zero comment names CBRD-20741; revision history also routes readers to CBRD-21135. Available evidence leaves the root cause unknown. Removing the forced-zero line alone is not a complete fix.

The retained comment “LRU + Aout of 2Q” describes design structure, not active startup behavior. Any revival needs concurrency, memory, policy, and measured-performance validation. Expected benefits are not measured performance claims.

Verified dormant source: system_parameter.c:3463–3474,9931–9987; page_buffer.c:635–666,5802–5903,6885–6994,10468–10636.

Code exists, but is the policy active?

Can the presence of AOUT structures explain a measured hit-rate change in the pinned server path?

Explore the explanation

Not by itself. AOUT is disabled in the pinned server path. Its dormant structures explain a possible ghost-history mechanism, not active workload behavior. Attributing a measurement to AOUT requires evidence that the measured build actually enables and executes that path.
