LECTURE 12A / Replacement

Dormant AOUT admission history

AOUT retains ghost admission metadata in the source, while pinned parameter tuning disables its operation.

Bonus: what AOUT could have contributed

Ghost metadataNo frameAdmission onlyForced off
01 · Short answer

AOUT is disabled in the pinned server path

The data structures remain in source, but startup forces data_aout_ratio = 0.0. Initialization allocates no ghost nodes, and add/lookup helpers return immediately. Active replacement is the INVALID/VOID/private/shared three-zone LRU path from Lecture 12.

AOUT is retained, disabled admission-history code. It neither stores page bytes nor chooses a victim in the pinned build.

Why remember a page after evicting it?

Inferred role: distinguish a stream of one-time scan pages from pages requested again soon after eviction. Both requests miss the resident buffer, but the second suggests that keeping the page longer could have avoided a miss. AOUT would use that feedback to choose how much initial protection a reloaded page receives.

  • Sequential scan: S1, S2, S3, … arrive once. Their later eviction records receive no matching request.
  • Repeated use: H1 is evicted, then requested while its ghost record still exists. The buffer misses, but AOUT remembers H1.

This is a plausible purpose derived from the retained branches, not proof of the original designers’ intent or a measured improvement. An absent record means “not remembered,” not “never reused.” The bounded FIFO measures recency through retained eviction records, not a wall-clock deadline.

02 · One ghost entry

A VPID and former LRU index are enough to remember a past eviction

{ VPID, former lru_idx, prev, next }

An entry contains no BCB, frame, latch, fix count, dirty generation, or page copy. The real BCB/frame pair may already represent another page. One global FIFO, free-node list, VPID hash, and Aout_mutex manage the records.

A = min(floor(N × data_aout_ratio), 32,768)
hash tables = max(floor(A / 1,000), 1)

With the pinned default ratio zero, A = 0. If enabled, the FIFO would recycle its oldest bottom entry when full.

03 · Retained design

A ghost hit would change first placement after reload

Decision point: the ordinary final unfix that reduces the global fcnt to zero and places a loaded VOID BCB. The table describes insertion before zone-boundary adjustment; special vacuum/direct-victim paths are outside this example. The private assignment is the final-unfix context’s assignment.

Reload contextRetained placement branch
Enabled private-LRU assignment; same-private ghost hitCurrent private LRU1 top
Enabled private-LRU assignment; AOUT missCurrent private LRU2 middle
Enabled private-LRU assignment; different former LRUShared LRU2 middle
No enabled private-LRU assignmentShared LRU2 middle

This is admission ranking after load. It does not select the old victim, prove ownership, or authorize reuse. AOUT-off removes the ghost hit/miss subdivision, not the two current paths: an enabled assignment reaches private LRU1 top and no enabled assignment reaches shared LRU2 middle.

Would remembering evictions help the scan example?

Hypothesis, with AOUT enabled: B reloads two pages under the same private assignment PB. H1 still has a ghost record from PB; S1 has none. Before boundary adjustment, H1 enters PB/LRU1 while S1 enters PB/LRU2. With AOUT off, both ordinary admissions enter PB/LRU1. No page bytes are cached in either ghost case: the miss and reload have already happened.

Expected trade-off, not a measured improvement

Admitting unremembered scan pages below LRU1 could reduce their interference with reused pages. A same-domain ghost hit can regain stronger initial protection. But a reused page whose ghost has expired is also a miss in that history, and a saved index can outlive the session that used it. A different former index routes the reload to shared LRU2, not to a private owner. These cases can change hit rate and competition in either direction.

The private/shared same-list reuse rules still apply afterward: LRU1 keeps, LRU2 tests age, LRU3 normally boosts, subject to migration and special unfix. AOUT changes admission evidence; it supplies no new guarantee of fairness, safe reuse or performance.

If AOUT were active: follow H1 once

  1. H1 leaves private list PB through eviction. Its frame becomes reusable; AOUT retains only { H1, PB } and queue links.
  2. H1 is requested again while that record survives. It is a buffer miss: bytes must be loaded into a frame before the page can be used.
  3. At ordinary final unfix, pgbuf_unlatch_void_zone_bcb() calls pgbuf_remove_vpid_from_aout_list(). A hit returns PB and consumes the record, returning its node to the free list.
  4. With current assignment PB, H1 enters private LRU1 top. Without the record it would enter PB/LRU2 middle; with a different former index it would enter shared LRU2 middle.

What this could change: stronger protection now may prevent a later miss. It cannot undo the reload that already happened, promise residency, or make an unsafe victim reusable.

04 · Evidence boundary

Reviving AOUT requires a new engineering review

The forced-zero comment names CBRD-20741; revision history also routes readers to CBRD-21135. Available evidence leaves the root cause unknown. Removing the forced-zero line alone is not a complete fix.

The retained comment “LRU + Aout of 2Q” describes design structure, not active startup behavior. Any revival needs concurrency, memory, policy, and measured-performance validation. Expected benefits are not measured performance claims.

Verified dormant source: system_parameter.c:3463–3474,9931–9987; page_buffer.c:635–666,5802–5903,6885–6994,10468–10636.

What must a revival experiment verify?
  • Trace the actual tuning, capacity, ghost hit/miss and first-placement branches; editing the ratio alone does not bypass forced-zero tuning.
  • Reproduce or retire the historical failure on the chosen revision. Stress FIFO/hash/free-node agreement, bounded capacity and node recycling under concurrent insertion and lookup/removal.
  • Exercise private-list release and reassignment, saved-index validity, same-domain and cross-domain reloads, and ordinary versus special unfix paths.
  • Compare enabled/disabled runs with the same pool and workloads: repeated working set plus scan, expired ghost history and cross-domain reuse. Measure misses, per-domain retention, memory and global Aout_mutex contention as well as throughput.

The older assertion/core is historical evidence with unknown root cause; reproduction in the dormant pinned implementation remains unconfirmed. These are verification tasks, not results from a new run. Read the retained source and historical evidence.

Code exists, but is the policy active?

Can the presence of AOUT structures explain a measured hit-rate change in the pinned server path?

Explore the explanation

Not by itself. AOUT is disabled in the pinned server path. Its dormant structures explain a possible ghost-history mechanism, not active workload behavior. Attributing a measurement to AOUT requires evidence that the measured build actually enables and executes that path.
