CUBRID page-buffer daemons and PostgreSQL page replacement

A small set of pages is read repeatedly while a large scan brings in other pages and writers leave dirty pages needing storage writes. Each constructed schedule starts independently; these examples are source reasoning, not recorded engine runs.

09 · 1 / 24

A full pool needs a candidate the scan can claim

A PostgreSQL request needs a scan page that is absent from memory, but every frame—a memory slot holding one page—is occupied. The requesting backend, a server process, must find a frame it can prepare for reuse.

Each frame has a buffer descriptor: metadata in a fixed array that records its current page identity and state. The page identity says which file block this frame represents. A pin keeps that identity from being replaced while a backend uses it. Shared refcount records lifetime pins and blocks Clock selection while nonzero. Ordinary backend use contributes one per backend with outstanding pins; unfinished asynchronous storage I/O can contribute an additional pin. It is not always a count of backend processes.

The Clock hand is a shared position for choosing the next descriptor to inspect. It advances atomically and wraps around the array. Descriptors and pages do not move around the array during this search.

An unpinned frame can still have reuse credit, stored in usage_count. Positive credit delays selection; it does not grant ownership. The search must distinguish “give another chance” from “acquire a pin.”

09 · 2 / 24

How does an observation become a protected claim?

A backend (server process) searching for a frame reads its descriptor, the metadata for that memory slot. To try a claim, it must see both refcount = 0 (no lifetime pins) and usage_count = 0 (no reuse credit). Another backend can change that state immediately after the read.

Compare-and-swap (CAS) is an atomic operation: change the shared state only if it still equals the saved expected state. Clock tries to add its pin this way. A successful CAS acquires lifetime protection; a failed CAS leaves its proposed update unapplied and supplies the current state for another decision.

The comparison covers the packed state word, not just the two displayed counters. Reading zero does not reserve a frame. Even a successful claim leaves the old page identity in place until later protected reuse checks succeed.

One hand visit has three possible outcomes

Reset to a new, quiet window of a larger pool. A, B and C are descriptor positions, each storing metadata for one memory frame. A pin prevents replacement of the current page identity; credit postpones selection. The hand, which chooses the next array position, starts at A. A has no pin and credit 2; B has a pin and credit 0; C has no pin or credit and no pending dirty write (it is clean). No storage I/O is in progress, no backend changes them, and no strategy ring supplies a candidate.

  1. At A, a successful compare-and-swap (CAS) reduces credit 2→1. The hand moves on without taking a pin.
  2. At B, the existing pin owner blocks both selection and credit reduction. The hand moves on.
  3. At C, CAS adds the requesting backend's pin. The descriptor still names its old page.

Clean means no pending dirty write is recorded; dirty means changed page bytes need writing. Before retiring a selected page identity, invalidation rechecks current ownership and dirty state under protection. A dirty candidate also needs conditional content locking and flushing; failed locking or validation causes retry.

09 · 9 / 24

Admission, later use and selection update different state

A descriptor stays paired with its frame while different page identities can occupy that frame over time. A pin protects the current identity; usage_count is bounded reuse credit. The credit example separates these events:

  1. Admission: after candidate selection and safe removal of the old identity, BufferAlloc assigns the new tag and sets usage_count = 1. The global Clock claim itself only adds a pin.
  2. Reuse: a backend's default first pin increases shared pin accounting and adds a credit, up to 5. A nested pin while it already holds the frame changes its private refcount only.
  3. Selection: the shared hand skips pin owners, spends one positive credit, or attempts to pin an unpinned zero-credit descriptor. Spending the last credit ends that visit; the claim needs a later visit.
  4. Bulk access: a backend-local strategy ring tries its stored shared-buffer IDs first for bulk read/write or vacuum. The IDs confer no private ownership of frames.
There is no exact LRU order: two descriptors with usage_count = 2 have no recorded older-first relation. Five credits can require five successful aging visits plus a later claim visit if nobody adds credit or changes pin ownership.

09 · 12 / 24

The source keeps ownership and retention separate

Consider one backend accessing a resident page and another searching for a reusable frame. Shared refcount records lifetime pins that prevent identity replacement; usage_count records retention credit. For ordinary backend pins, each backend contributes one while its private refcount records nested uses. All those uses must be released before its shared contribution disappears.

AIO (asynchronous I/O) lets a storage operation continue while its issuing backend proceeds or enters error cleanup. The I/O subsystem adds a lifetime pin so cleanup cannot make that frame reusable while storage still uses it; the I/O termination path releases this pin. Shared refcount therefore need not equal the number of backends. The numerical teaching traces assume no I/O in progress.

AIO lifetime pin · I/O pin release

On a default first pin, PinBuffer adds a shared pin and increases credit unless it is already 5. With a strategy object, it raises zero credit to 1 and preserves any higher value. A nested pin changes only private accounting, so repeated nesting earns no extra shared credit.

For global selection, the atomic hand supplies a descriptor visit. Clock skips a nonzero pin count. Otherwise it waits if the descriptor header (the protected metadata) is locked, then uses CAS—compare-and-swap against the read state—to decrement positive credit or add a pin at zero credit. Successful decrement ends the visit; successful claim records ownership and returns the descriptor. Failed CAS retries with current state.

Verified mechanism / Implementation policy: bufmgr.c:3295–3386 · freelist.c:239–317 · packed state and maximum credit. This revision uses 64-bit packed state, including content-lock state; older spinlock summaries are not the executable authority.

The shared hand assigns work to concurrent allocators

Two backends (server processes) need frames for missing pages. A frame is a memory slot; its descriptor holds metadata. The global Clock hand, stored in nextVictimBuffer, remembers the next descriptor position to inspect.

Each ClockSweepTick atomically takes a position and advances that shared counter. Different allocators can then inspect different descriptors concurrently; taking a position does not claim its frame. Positions wrap around the array, so descriptors can be visited again.

A spinlock protects the brief wrap/pass bookkeeping: one process updates the shared pass record at a time. It is not held through candidate aging and claiming. Those actions use atomic state on each descriptor; the next screen follows one race.

An ordinary resident hit, finding the requested page already in the pool, pins that page without advancing the hand. The shared hand is part of global candidate search, not every access.

Exact LRU pays for an order on accesses

Teaching alternative: suppose a shared doubly linked list orders resident frames by the last access event the design chooses to record. LRU means “least recently used”; move a frame toward the most-recent end on each such event. This retains an older-first relation that Clock's reuse credits do not record.

If the node is already known, relinking it takes O(1) pointer work: a constant number of links, regardless of pool size. Concurrent backends still need synchronization so their list changes form one consistent order. This adds link storage and shared metadata writes on hits.

Clock instead updates bounded credit and delays aging until a backend searches for a candidate. Its shared hand and compare-and-swap (CAS) state updates also cost work. Source structure alone does not establish which design is faster under a particular workload.

09 · 16 / 24

Changing preference need not weaken reuse safety

A replacement policy chooses which eligible frame to prefer. Lifetime protection and data preservation decide whether that frame can actually be reused.

FIFO prefers the earliest admitted page. A zero-credit Clock removes retention credit and selects at the next unpinned visit. Either can retain pin checks, content locking for page bytes, WAL (write-ahead log) ordering that preserves recovery records before page writes, and protected identity removal. Removing only credit changes victim preference; it does not inherently corrupt pages.

Counting every nested pin in shared state is another coherent lifetime design if releases match acquisitions. It adds shared atomic work and changes the counter's meaning; it does not make credit into ownership.

CLOCK-Pro and 2Q study richer replacement history with extra policy state. They describe alternatives, not either pinned engine's active policy or a performance result for this workload.

Count visits and retries before comparing costs

To evaluate a search, separate reaching a descriptor from successfully changing its state. A concurrent backend may force several compare-and-swap (CAS) retries at one descriptor.

V counts descriptor visits, R counts failed CAS attempts, and N is the number of buffers in the pool. These are analysis quantities, not extra stored fields. Selection performs O(V + R) state operations: work grows with visits plus retries.

This count excludes waiting for a descriptor header lock, content-lock waits and writing dirty pages to storage. Descriptor policy state uses O(N) memory, proportional to the pool size; each backend also keeps private use state.

Cost hypothesis (Inference): Clock avoids exact-recency list splices on ordinary hits. Many global misses can contend on the shared hand or revisit credited pages; many first pins on one page can contend on its descriptor state. CUBRID spreads replacement-list work across policy domains (groups for retention accounting), while still synchronizing BCBs (frame control records), lists and quota budgets. Measure under a stated workload; these mechanisms establish no performance ranking.

A quiet pool gives a bound on visits

Start an independent, quiet search: one allocating backend moves the hand; pin owners do not change; at least one descriptor stays unpinned; nobody adds credit; and state operations succeed without waiting or interference.

N is the number of descriptors in this pool, and U is the largest allowed starting reuse credit. These are teaching-model quantities. Here U=5. A pin blocks selection; positive credit is reduced by one at a successful aging visit.

  1. Choose a descriptor that stays unpinned. Every full sweep of N visits reaches it.
  2. It needs at most U successful decrements to reach zero. Each decrement resets trycounter, the selector's budget for pinned observations.
  3. The next visit claims it. Thus N(U+1) is a loose bound on visits; finding another candidate earlier only shortens the search.

Inference under these premises: visiting the chosen descriptor also interrupts any run of N pinned observations, so the pinned-only error cannot occur first. This is a bound on work in this quiet model, not elapsed time.

09 · 19 / 24

Concurrent use breaks the quiet search premises

A pin preserves the current page identity, while reuse credit postpones selection. The quiet model assumes no new credit and unchanged pin ownership. In a real concurrent search, other backends can pin a candidate, replenish credit, take hand positions and change shared state before a compare-and-swap (CAS) succeeds.

N is the pool's descriptor count. trycounter starts at N. Observing a pinned descriptor decreases it; a successful credit decrement restores it to N. It is a budget for pinned observations since the last successful aging step, rather than a total-visit cap.

If pinned observations exhaust that budget, the source reports “no unpinned buffers available.” It describes the sequence this selector encountered; those observations need not describe one simultaneous snapshot, and they do not prove permanent exhaustion.

Credit never exceeding 5 does not bound how often others renew it or how often CAS fails. The source establishes neither fairness for a particular allocator nor a maximum allocation latency.

Build exact recency without losing reuse checks

Teaching alternative: replace Clock's retention credit with a shared doubly linked order. Its MRU end is most recently used; its LRU end is least recently used. Keep pins for identity lifetime, locks for byte access, and dirty-write obligations for changed pages. Write-ahead-log protection preserves recovery records before page writes.

  1. Define the successful access event that counts as recent. Synchronize each such event into one consistent MRU/LRU order.
  2. Search from the oldest end, skipping pinned frames. Take a protected pin on the chosen candidate before preparing reuse.
  3. Write dirty bytes with required content and write-ahead-log protection. Under protected current-state checks, retire the mapping from old page identity to frame only if no competing pin or dirty change blocks it.
  4. After interference or write failure, retain the page identity and any unfinished write obligation. Keep the list consistent, release the attempted ownership correctly, and retry.

N is the number of resident frames. This alternative needs O(N) list metadata, O(1) relinking per chosen access under shared synchronization, and up to O(N) eligibility scans. History-aware alternatives also record identities of pages no longer resident. Exact order alone does not establish fairness.

Record the full pinned revision, build, pool size, workload and relevant log/I/O settings. Probes can change scheduling; record their overhead. For cross-engine runs, also record any DWB (double-write buffer) staging.

Hypothesis
The quiet bound applies with one allocator, fixed pin owners, no added credit and successful state operations. Concurrent replenishment or CAS interference can remove that bound.
Controlled change
Reset to the same initial pin counts, credit vector and hand position for every run. First run an isolated sweep; then independently introduce pin changes, credit replenishment or claim interference.
Exact observation
Add a proposed descriptor probe for hand visits, observed pins/credit, skip/decrement/claim outcomes, CAS failures and trycounter resets. numBufferAllocs counts allocation requests after ring fallback, excludes ring recycling, and does not count visits.
Falsifier and limit
Exceeding the bound with every quiet premise intact refutes the derivation. Returning a Clock candidate without successful protected claim refutes that mechanism. After interference, identify the changed premise; extra visits then do not refute the quiet proof. These runs establish no fairness or general speed.
