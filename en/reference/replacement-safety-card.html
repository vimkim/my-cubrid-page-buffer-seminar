BCB identity in one sentence

Stable slot, one current VPID: a BCB/frame address is reused serially—A, detached, then B—never as two resident page identities at once.

QuestionAnswer
Can many threads hold it?Yes, for the same current page when latch rules permit.
Can it represent many VPIDs simultaneously?No.
Can it be in private and shared LRUs simultaneously?No. One link pair plus one encoded list index represent one membership. A move removes to VOID before adding to the other list.
Why protect the handoff?The scan only nominates a pointer. BCB try-lock and recheck establish current all-clear state, then detach returns the BCB still locked so an old A-based decision cannot act after ownership/state change or rebind to B.

Eligibility gates policy

Hard predicates

  1. Identity still matches candidate.
  2. No fix owner or transient right remains.
  3. No DIRTY or FLUSHING generation debt remains.
  4. No conflicting waiter exists.
  5. All conditions pass again under BCB protection.

Policy inputs

  • LRU placement and victim zone
  • Private versus shared domain
  • Quota and “another chance” decisions
  • Candidate queues and hints
  • Revocable direct assignment

Policy ranks eligible frames; it never repairs failed eligibility.

Four fast counterexamples

  • fcnt == 0 + DIRTY → unpropagated debt
  • fcnt == 0 + FLUSHING → in-flight identity
  • fcnt == 0 + waiter → pending right
  • All clear before BCB lock → only an earlier sample; recheck after try-lock

Verb test

  • Unfix: repay one ownership debt.
  • Flush: propagate one copied generation.
  • Victimize: detach safe frame for reuse.
  • Invalidate: remove/reject mapping for coherence.
  • Deallocate: end logical storage ownership.
