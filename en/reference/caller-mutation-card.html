Six-step mutation spine

Two protections

  • Page latch: current resident-byte access; ends with watcher release/transfer.
  • Transaction lock: logical class or row protocol; ends with transaction policy.
  • Holding either never implies holding the other.

Success ordering

  1. Prepare and take logical lock.
  2. Acquire and validate destination.
  3. Mutate resident page format.
  4. Append recovery log; advance page LSA when required.
  5. Mark resident generation DIRTY.
  6. Transfer or release every watcher.

Four non-equivalences

  • WRITE latch ≠ logical ownership
  • Mutation ≠ recovery logging
  • Page LSA ≠ DIRTY publication
  • Unfix ≠ commit or flush

Exit-ledger columns

  1. Exact exit seam
  2. State already acquired or created
  3. Consumer, transfer, or cleanup owner
  4. Remaining recovery/retry consequence
  5. Evidence boundary or helper dependency
