1 / 6 · Problem and invariant

A scan needs space without earning unlimited retention

A one-pass scan can bring many pages through a shared pool while reusing few of them. If each visit earns normal clock credit, the scan may displace a repeatedly used working set. Strategy rings bound the scan's preferred reuse footprint using backend-local shared-buffer IDs, not a separately allocated private cache.

Policy: Try local ring slots with shared refcount=0 and credit≤1; higher credit suggests other use. Safety: Claim through shared state, preserve dirty data/WAL, then retire the old mapping under protected current-state checks.

Two local rings can name F4. Neither owns F4 permanently. Successful pin CAS by one makes the other's slot temporarily unusable. An ID can later name a different page in the same shared frame.

2 / 6 · Mechanism and evidence

A ring hit only completes selection

Advance the local slot; empty, pinned or high-credit entries fall back to the global clock and replace that slot with the selected ID. BAS_NORMAL has no ring. BULKREAD, BULKWRITE and VACUUM have source-selected sizes; bulk-read sizing includes I/O concurrency expansion and caps, so “always 256 KiB” is not valid at this pin.

The selected descriptor already has this backend's pin. A dirty victim needs a conditional share-exclusive content lock. Failure releases the pin and retries, avoiding a possible wait cycle described in the source. A permanent BULKREAD ring victim needing WAL flush may be rejected and its slot invalidated. Otherwise FlushBuffer observes the page LSN and flushes WAL before the permanent-page write.

4 / 6 · Alternatives and costs

A local footprint and a local pool are different alternatives

No ring: Keep the normal clock and all safety checks. Scan traffic now uses normal allocation/credit paths; pollution and metadata traffic may increase, but correctness can remain intact. Teaching alternative: Allocate a separate private scan pool. This isolates capacity but duplicates cached bytes and needs coherence if writers and normal readers access the same pages. A shared admission policy could instead deprioritize one-touch pages, adding classification/history state.

Ring memory is O(r) IDs per strategy object of r slots; a slot attempt does O(1) local work plus shared-state CAS retries. Fallback adds clock visits. It reserves no r exclusive shared frames. Avoiding high-credit IDs is a policy choice; bypassing pinned checks is a lifetime error.

An alternative that eliminates backend eviction writes needs guaranteed clean supply or explicit wait/failure when none exists. Moving I/O to another actor does not eliminate it.

Successful writes and OS writeback scheduling are distinct from durable storage. The final InvalidateVictimBuffer check requires refcount exactly one and no BM_DIRTY under mapping/header locks. A new user can dirty R and leave before this check, restoring refcount one while retaining debt.

6 / 6 · Defense and falsifiability

D30 / D31 · Defend footprint and retirement separately

Two rings contain F4, now unpinned with credit 2. Can both reuse it because their IDs are local?

Reveal the ring argument

No. Local IDs confer no ownership and current credit>1 rejects both ring attempts. With credit≤1, a successful claim by one still changes shared refcount; the other must re-evaluate. Removing only the credit gate changes retention policy; removing the pin gate threatens lifetime.

Follow-up: BAS_BULKREAD WAL rejection invalidates its own current slot, preventing repeated selection of the same costly dirty ring entry. It neither clears the shared dirty page nor changes every strategy.

A's write succeeded; B later re-dirtied and unpinned R. Is refcount=1 sufficient for retirement?

Reveal the retirement argument

No. Current BM_DIRTY also rejects reuse. A valid optimization must exclude intervening dirties or preserve their image through another protocol. Count ring hits, fallback visits, content-lock rejection, WAL rejection and dirty/refcount invalidation separately to discriminate scan pressure from writeback races.
