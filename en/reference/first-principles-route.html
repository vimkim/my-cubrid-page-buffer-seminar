How to read the examples and arrows

A code arrow is a verified direct caller → callee edge on the stated branch. A branch diagram is not one simultaneous stack. A queue handoff crosses execution contexts. Source paths are not debugger captures. Textbook traces are abstract; the database examples are bounded constructed states, not measurements or claims about tiny supported pool sizes.

Misleading shortcuts to leave behind

ShortcutPrecise explanation and evidence
“LRU means exact last-access order.”CUBRID has domains, zones, and conditional movement. It does not maintain one global exact-LRU rank. Evidence →
“Private means only my session may access it.”It is a residency/quota domain in the common pool; access protection remains separate. Evidence →
“BCB array and LRU array are the same thing.”One owns frame control records; the other owns list descriptors that link them. Evidence →
“Zero fix count means immediately reusable.”Dirty/flushing state, waiters, flags, locks, and protected revalidation still matter. Evidence →
“Unfix, flush, eviction, and commit are synonyms.”They end use, propagate an image, remove residency, and complete a transaction respectively. Evidence →
“Post-flush writes the page again.”It consumes a BCB pointer and completes state work; the queue is an asynchronous boundary. Evidence →
“Flush-control grants permission before writing.”Participating writers consume credits after a successful OS write. Evidence →
“A flush completion proves the current page is clean.”A later generation may be dirty. DWB acceptance also differs from home-page completion. Evidence →
“CUBRID always runs active 2Q/AOUT.”The pinned parameter tuning forces AOUT off; dormant code is not active behavior. Evidence →
“Maintenance guarantees backup direct victims.”VS-20 records loops that skip their bodies at this pin. Other producers remain; no runtime starvation is proved. Evidence →
“The 1,000 limit bounds the whole allocation.”It bounds BCB visits in one selected-list scan; other list attempts and pre-scan demotions are separate. Evidence →
“A miss proves physical disk I/O; a hit cannot wait.”Lower caches can satisfy reads; resident pages can still require latch waits. Evidence →

Explain one missing page from beginning to end

Request P → resident lookup → if absent, acquire a frame → prefer an invalid slot, otherwise select a domain and eligible victim → protected recheck → remove the old mapping → materialize P → grant access → unfix after use. When changes remain, WAL-ordered cleaning can prepare future reuse; a completed flush does not itself mean eviction.
