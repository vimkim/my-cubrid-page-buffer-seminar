What “private domain” means

A session or worker borrows a private-list number; the thread carries it in private_lru_index. The BCB stores one current LRU/zone, not a session owner. Multiple sessions may share one private LRU, and releasing an assignment does not empty or move its BCBs.

Final-unfix placement

Ordinary movement starts only when global fcnt reaches zero. First placement is private LRU1 top or shared LRU2 middle. Domain mismatch and hot-plus-old private members move private → VOID → shared middle while the BCB mutex remains held.

Domains and search policy

Separate scan depth from list count

Quantities

  • N BCB/frame pairs; startup invalid count = N
  • L = S + P persistent LRU objects
  • P is not capped at 1,000; auto = MAX_NTRANS + 50, explicit max = 4,050
  • Private Q: LRU1 5%, LRU2 5%
  • Shared target: LRU1 40%, LRU2 5% by default
  • One private Q ≤ min(5,000, N/2)

Costs

  • invalid head: O(1)
  • known LRU link edit: O(1) + demotions
  • private assignment: O(P)
  • quota pass: O(T + S + P + demotions)
  • shared choice: amortized O(1), periodic O(S)
  • shared placement/migration: amortized O(1 + D), periodic O(S + D)
  • hit registrar / move predicate: O(1)
  • resident fix: O(hash chain H + holder list R), before waits
  • unfix: O(R + waiter scan W) + placement work
  • one selected-list scan: ≤ 1,000 LRU3 BCB visits
  • whole helper: O(demotions + bounded scan)
  • cross-private discovery: no all-P scan

Allocator exits

  1. Invalid/free BCB success
  2. Eligible LRU victim success
  3. Direct reservation then success
  4. Revocation then retry
  5. Interrupt/shutdown
  6. Timeout
  7. Synchronous flush/search without daemon
  8. Explicit no-buffer error

adjust_age

Only an accepted pgbuf_adjust_quotas() pass increments this epoch. A 100-ms daemon call may return at a gate. One BCB contributes at most one hit to its current LRU per epoch; the next pass takes and resets list hits with ATOMIC_TAS_32.

Direct-victim rule

Assignment is a reservation.

  1. Producer checks eligibility.
  2. Consumer later locks/revalidates.
  3. Any intervening fix revokes assignment.
  4. Allocator requests another candidate.

Generation rule

Post-flush may assign only after rechecking current resident state. Completion of copied G never authorizes reuse when resident G+1 is DIRTY.

AOUT status and dormant admission

Pinned state: startup forces data_aout_ratio = 0; no ghost storage is allocated. Historical CBRD-20741 records the assertion/core, and CBRD-21135 records the decision to disable AOUT while the root cause was unknown. If safely enabled, a private AOUT miss would enter middle, a same-private refault top, and an other-private refault shared middle. These are dormant source branches, not measured gains. Revival must repair and stress the invariants and measure the single global Aout_mutex; deleting the forced-zero line alone is not a fix.

Evidence boundaries for promotion claims

  • queue priority → starvation freedom
  • daemon loop → stable cadence
  • AOUT structures → active 2Q default
  • reuse counters → observed eviction
  • victim hint → eligibility proof
