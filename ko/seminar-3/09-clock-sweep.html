Clock: 검사, 감소, 건너뛰기, 확보

CUBRID 페이지 버퍼 daemon과 PostgreSQL 페이지 교체

소수의 페이지를 반복해서 읽는 동안 대량 스캔이 다른 페이지를 가져오고, 쓰기 작업은 저장소에 기록해야 할 dirty 페이지를 남깁니다. 구성한 실행 순서는 각각 독립적으로 시작합니다. 이 예제는 소스로 추론한 설명이며, 엔진에서 기록한 실행 결과가 아닙니다.

09 · 1 / 24

가득 찬 풀에서 스캔이 확보할 후보를 찾습니다

PostgreSQL 요청이 메모리에 없는 스캔 페이지를 필요로 합니다. 하지만 모든 프레임은 페이지 하나를 담는 메모리 슬롯이며 모두 이미 페이지로 차 있습니다. 요청을 처리하는 backend는 서버 프로세스로서 재사용을 준비할 프레임을 찾아야 합니다.

각 프레임에는 buffer descriptor가 있습니다. 고정 배열에 놓인 이 메타데이터는 프레임의 현재 페이지 식별자와 상태를 기록합니다. 페이지 식별자는 그 프레임이 어떤 파일 블록을 나타내는지 알려 줍니다. pin은 backend가 사용하는 동안 그 식별자가 교체되지 않도록 보호합니다. 공유 refcount는 수명을 보호하는 pin을 기록하며, 0이 아니면 Clock 선택을 막습니다. 일반적인 backend 사용에서는 pin을 보유한 backend마다 하나씩 기여합니다. 아직 끝나지 않은 비동기 저장소 I/O도 별도 pin 하나를 더할 수 있으므로, 이 값이 항상 backend 프로세스 수인 것은 아닙니다.

Clock hand는 다음에 검사할 descriptor를 고르는 공유 위치입니다. 원자적으로 전진하며 배열 끝에 도달하면 처음으로 돌아갑니다. 이 탐색 중에 descriptor나 페이지가 배열 안에서 이동하는 것은 아닙니다.

Pin이 없는 프레임에도 재사용 크레딧이 남아 있을 수 있습니다. 선택을 미루는 추가 기회이며 usage_count에 저장됩니다. 양수 크레딧은 선택을 늦출 뿐 소유권을 주지 않습니다. 따라서 “한 번 더 기회를 주기”와 “pin을 얻기”를 구분해야 합니다.

관찰한 상태를 어떻게 보호된 확보로 바꿀까요?

프레임을 찾는 backend(서버 프로세스)는 그 메모리 슬롯의 메타데이터인 descriptor를 읽습니다. 확보를 시도하려면 refcount = 0(수명 보호 pin 없음)과 usage_count = 0(재사용 크레딧 없음)을 모두 확인해야 합니다. 읽은 직후에도 다른 backend가 상태를 바꿀 수 있습니다.

Compare-and-swap(CAS)는 저장해 둔 기대 상태와 현재 공유 상태가 같을 때만 값을 바꾸는 원자적 연산입니다. Clock은 이 연산으로 자신의 pin을 추가합니다. CAS가 성공하면 페이지 식별자의 수명을 보호하게 됩니다. 실패하면 제안한 변경은 적용되지 않으며, 현재 상태를 받아 다시 판단합니다.

비교 대상은 표시한 두 counter뿐 아니라 상태를 묶어 저장한 전체 word입니다. 0을 읽었다고 프레임을 예약한 것은 아닙니다. 확보에 성공해도 이후의 보호된 재사용 검사가 성공하기 전까지는 기존 페이지 식별자가 유지됩니다.
09 · 3 / 24

첫 pin은 상한이 있는 재사용 크레딧을 더합니다

저장소 I/O가 없는 독립 예제입니다. H1과 H2는 반복해서 읽는 페이지의 식별자입니다. H1을 공유 프레임(메모리 슬롯)에 새로 들여와 적재한 뒤 pin을 모두 해제한 상태에서 시작합니다. 진행 중인 저장소 I/O는 없습니다. 다른 주체는 이를 바꾸지 않으며, 이후 두 번의 접근 사이에 Clock 방문도 없습니다.

pin은 현재 페이지 식별자가 재사용으로 바뀌지 않도록 보호합니다. Backend(서버 프로세스)가 pin을 하나도 보유하지 않은 상태에서 얻는 것이 첫 pin입니다. 이미 pin을 보유한 채 사용을 하나 더 추가하면 중첩 pin입니다. usage_count는 재사용 크레딧을 저장합니다. 여기서 이후의 각 접근은 앞선 pin을 모두 해제한 뒤 기본 전략으로 수행합니다.

usage_count = 1

기본 전략의 첫 pin은 크레딧을 하나씩 더하며 상한은 5입니다. 중첩 pin은 backend 내부의 사용 횟수만 늘리므로 공유 크레딧을 더 얻지 않습니다.

Hand는 확보를 시도하기 전에 크레딧을 씁니다

앞선 예제를 이어갑니다. H1과 H2는 반복해서 읽는 페이지의 식별자입니다. 이제 H1의 크레딧은 3이고 수명 보호 pin은 없습니다. 진행 중인 저장소 I/O도 없습니다. 접근을 멈추며, 아래 방문 중에는 누구도 크레딧을 더하거나 pin하지 않습니다.

Clock hand는 고정 배열에서 descriptor 위치를 고릅니다. Descriptor는 메모리 프레임 하나의 메타데이터입니다. Aging은 pin이 없는 프레임을 방문할 때마다 usage_count(재사용 크레딧)를 하나씩 줄이는 일입니다. CAS(compare-and-swap)는 읽었던 전체 공유 상태와 현재 상태가 같을 때만 변경을 적용합니다.

Pin 없이 hand가 방문

3 → 2 → 1 → 0

방문마다 크레딧 하나를 쓰고 이동
0인 상태에서 이후 방문

확보 시도

CAS 시점에도 pin과 크레딧이 없어야 함

Aging은 몇 초가 지나서 일어나는 것이 아니라 방문할 때 일어납니다. 1→0으로 줄인 방문에서도 pin을 얻지 않고 넘어갑니다. 이후 방문에서 여전히 소유자와 크레딧이 없으면 보호된 확보를 시도할 수 있습니다.

반복해서 사용하는 H1/H2는 한 번만 읽는 스캔 페이지보다 기회를 더 얻을 수 있습니다. 하지만 크레딧이 2인 두 페이지 사이에는 “어느 쪽이 더 최근인가”라는 순서가 기록되지 않습니다. Hand 위치가 어느 페이지를 먼저 만나는지에 영향을 줍니다.

09 · 5 / 24

Hand의 한 번 방문에는 세 가지 결과가 있습니다

더 큰 풀의 일부 구간을 보는 새 예제로 초기화합니다. 동시 변경은 없습니다. A, B, C는 descriptor 위치이며, 각각 메모리 프레임 하나의 메타데이터를 저장합니다. Pin은 현재 페이지 식별자의 교체를 막고, 크레딧은 선택을 미룹니다. 다음 배열 위치를 고르는 hand는 A에서 시작합니다. A는 pin이 없고 크레딧이 2입니다. B는 pin이 있고 크레딧이 0입니다. C는 pin과 크레딧이 모두 없으며, 기록할 dirty 변경도 없는 clean 상태입니다. 진행 중인 저장소 I/O가 없고, 어떤 backend도 이 상태를 바꾸지 않으며, strategy ring이 후보를 제공하지도 않습니다.

  1. A에서는 compare-and-swap(CAS)가 성공해 크레딧을 2→1로 줄입니다. Hand는 pin을 얻지 않고 이동합니다.
  2. B에서는 기존 pin 소유자가 선택과 크레딧 감소를 모두 막습니다. Hand는 이동합니다.
  3. C에서는 CAS로 요청 backend의 pin을 추가합니다. Descriptor는 여전히 기존 페이지를 가리킵니다.

Clean은 기록해야 할 dirty 변경이 남아 있지 않은 상태입니다. Dirty는 바뀐 페이지 바이트를 저장소에 기록해야 하는 상태입니다. 선택한 페이지 식별자를 제거하기 전에 invalidation은 현재 소유권과 dirty 상태를 보호한 상태에서 재검사합니다. Dirty 후보라면 조건부 content lock과 flush도 필요합니다. Lock 획득이나 검증이 실패하면 재시도합니다.

페이지 miss는 victim 경로를 거쳐 Clock에 도달합니다

시작 상태에서 요청한 페이지는 공유 풀에 없습니다. PinBufferForBlock은 BufferAlloc을 호출해 메모리에 둘 공간을 찾거나 배정합니다. Miss이면 GetVictimBuffer가 StrategyGetBuffer에 pin한 후보를 요청합니다. 전역 경로에서는 ClockSweepTick으로 다음 descriptor 위치를 고릅니다.

Descriptor는 프레임 하나의 메타데이터이고, 프레임은 페이지 바이트를 담는 메모리 슬롯입니다. Hand는 메타데이터 배열을 따라 전진합니다. Pin은 현재 식별자를 보호하고, 재사용 크레딧은 선택을 미룹니다. 후보 선택 뒤에도 dirty 페이지 기록과 보호된 기존 식별자 제거가 남아 있습니다.

Pin은 선택을 막고 크레딧은 선택을 미룹니다

감소, 건너뛰기, 감소, 그리고 확보

독립적으로 초기화합니다. F0, F1, F2, F3는 descriptor와 프레임의 위치로, 메타데이터와 메모리 슬롯이 짝을 이룹니다. 각각 반복 사용하는 페이지 식별자 H1과 스캔 페이지 식별자 S1, S2, S3를 담습니다. 모두 clean입니다. 다른 backend가 F1의 pin을 계속 보유하며, 프레임을 찾는 backend는 pin이 없습니다. Hand는 F0에서 시작합니다. 진행 중인 저장소 I/O나 동시 간섭은 없습니다.

각 행은 페이지 식별자 / pin 소유자 수(ref) / 재사용 크레딧(usage) 순서입니다. Pin은 식별자를 보호합니다. CAS는 읽은 상태와 비교하는 원자적 연산으로, 양수 크레딧을 쓰고 이동하거나 두 counter가 모두 0일 때 pin을 더합니다. 확보해도 식별자는 그대로입니다.

탐색을 평가하려면 descriptor에 도달하는 일과 상태 변경의 성공을 나눠야 합니다. 동시 backend 때문에 한 descriptor에서 compare-and-swap(CAS)를 여러 번 재시도할 수 있습니다.

V는 descriptor 방문 수, R은 실패한 CAS 시도 수, N은 풀의 buffer 수입니다. 분석용 수량이며 따로 저장하는 필드가 아닙니다. 선택은 O(V + R)의 상태 연산을 수행합니다. 방문과 재시도가 많을수록 작업도 늘어납니다.

이 수량에는 descriptor header lock 대기, content lock 대기, dirty 페이지의 저장소 기록은 포함되지 않습니다. Descriptor의 정책 상태는 풀 크기에 비례하는 O(N) 메모리를 사용하며, 각 backend도 내부 사용 상태를 유지합니다.

비용 가설(Inference): Clock은 일반적인 hit에서 정확한 최근 순서를 유지하기 위한 리스트 연결 변경을 피합니다. 전역 miss가 많으면 공유 hand에서 경쟁하거나 크레딧이 남은 페이지를 다시 방문할 수 있습니다. 한 페이지에 첫 pin이 몰리면 그 descriptor 상태에서 경쟁할 수 있습니다. CUBRID는 보유량을 계산하는 그룹인 정책 영역들에 교체 리스트 작업을 나눕니다. 그래도 프레임 제어 기록인 BCB, 리스트와 영역별 보유량 목표인 quota 예산은 동기화합니다. 명시한 workload에서 측정해야 하며, 이 메커니즘만으로 성능 순위가 성립하지는 않습니다.

CLOCK-Pro와 2Q는 기본 Clock에 없는 교체 이력 상태를 더합니다. 논문은 대안을 설명하며, 고정한 엔진의 실제 활성 정책이나 이 workload의 속도 향상을 입증하지 않습니다.

동시 변경 없는 풀에서는 방문 상한을 구할 수 있습니다

독립적인 탐색을 시작하며 동시 변경이 없다고 가정합니다. 프레임을 찾는 backend 하나만 hand를 이동합니다. Pin 소유자가 바뀌지 않고, 적어도 한 descriptor는 계속 pin이 없습니다. 누구도 크레딧을 더하지 않으며, 상태 연산은 대기나 간섭 없이 성공합니다.

N은 이 풀의 descriptor 수이며 U는 시작 시 허용하는 최대 재사용 크레딧입니다. 설명 모델의 수량입니다. 여기서는 U=5입니다. Pin은 선택을 막고, 양수 크레딧은 성공한 aging 방문마다 하나씩 줄어듭니다.

  1. 계속 pin이 없는 descriptor 하나를 고릅니다. N번 방문하는 전체 sweep마다 이를 만납니다.
  2. 최대 U번 감소에 성공하면 크레딧이 0이 됩니다. 각 감소는 trycounter를 초기화합니다. 이는 선택자가 pin 있는 descriptor를 관찰할 때 쓰는 예산입니다.
  3. 다음 방문에서 확보합니다. 따라서 N(U+1)이 느슨한 방문 상한입니다. 다른 후보를 먼저 찾으면 탐색은 더 짧아집니다.

이 전제 아래의 추론(Inference): 고른 descriptor의 방문은 pin 있는 descriptor를 연속 N번 관찰하는 흐름도 끊습니다. 따라서 pinned-only 오류가 먼저 발생할 수 없습니다. 이 상한은 동시 변경 없는 모델의 작업량이며 경과 시간의 상한이 아닙니다.

동시 사용은 앞선 탐색 전제를 바꿉니다

Pin은 현재 페이지 식별자를 보호하며, 재사용 크레딧은 선택을 미룹니다. 앞선 모델은 새 크레딧이 없고 pin 소유자가 그대로라고 가정합니다. 실제 동시 탐색에서는 다른 backend가 후보를 pin하고 크레딧을 보충하며 hand 위치를 가져갑니다. Compare-and-swap(CAS)가 성공하기 전에 공유 상태도 바꿀 수 있습니다.

N은 풀의 descriptor 수입니다. trycounter는 N에서 시작합니다. Pin이 있는 descriptor를 관찰하면 하나 줄고, 크레딧 감소가 성공하면 다시 N이 됩니다. 마지막 aging 성공 이후의 pin 관찰 예산이며 전체 방문 횟수의 상한은 아닙니다.

Pin 관찰로 그 예산을 다 쓰면 소스는 “no unpinned buffers available” 오류를 냅니다. 이는 이 선택자가 만난 관찰 순서를 설명합니다. 관찰들이 같은 순간의 전체 상태를 나타낼 필요는 없으며 영구 고갈을 입증하지도 않습니다.

크레딧이 5를 넘지 않아도 다른 주체의 보충 횟수나 CAS 실패 횟수가 제한되지는 않습니다. 소스는 특정 할당자의 공정성이나 최대 할당 지연을 입증하지 않습니다.

재사용 검사를 유지하면서 정확한 최근 순서를 만듭니다

설명용 대안: Clock의 보유 크레딧을 공유 이중 연결 순서로 바꿉니다. MRU 쪽은 가장 최근에 사용한 쪽이며 LRU 쪽은 가장 오래 전에 사용한 쪽입니다. 식별자 수명을 위한 pin, 바이트 접근을 위한 lock, 바뀐 페이지의 dirty 기록 의무는 유지합니다. Write-ahead log 보호는 페이지 기록 전에 복구용 log를 보존합니다.

  1. 최근 사용으로 셀 성공한 접근 사건을 정의합니다. 그런 사건마다 하나의 일관된 MRU/LRU 순서에 반영하도록 동기화합니다.
  2. 오래된 쪽부터 탐색하며 pin한 프레임은 건너뜁니다. 재사용을 준비하기 전에 선택한 후보에 보호된 pin을 얻습니다.
  3. 필요한 content 보호와 write-ahead log 순서를 지키며 dirty 바이트를 기록합니다. 현재 상태를 보호한 상태에서 검사하며, 다른 pin이나 dirty 변경이 막지 않을 때만 기존 페이지 식별자와 프레임의 mapping을 제거합니다.
  4. 간섭이나 기록 실패가 생기면 페이지 식별자와 미완료 기록 의무를 보존합니다. 리스트를 일관되게 유지하고 시도 중 얻은 소유권을 올바르게 해제한 뒤 재시도합니다.

N은 메모리에 있는 프레임 수입니다. 이 대안에는 O(N) 리스트 메타데이터, 선택한 접근마다 공유 동기화 아래 O(1) 연결 변경, 최대 O(N) 적합성 탐색이 필요합니다. 이력을 기억하는 대안은 메모리에서 나간 페이지 식별자도 기록합니다. 정확한 순서만으로 공정성이 성립하지는 않습니다.

Hypothesis
