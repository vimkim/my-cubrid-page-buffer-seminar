Checkpoint와 redo gate

log의 의미와 allocation history는 recovery가 소유하고, 반복되는 page 변경은 page LSA가 gate한다.

Redo page-LSA gate

Checkpoint ownership

  • Page buffer: 조건에 맞는 page를 선별해 flush하고 남은 redo floor를 보고한다.
  • Log/filesystem/volume owner: checkpoint record, WAL/header state, filesystem sync, metadata boundary를 담당한다.

checkpoint는 모든 page를 flush하는 작업이 아니다.

Generic redo 흐름

  1. RECOVERY_PAGE를 WRITE로 fix한다.
  2. target이 없거나 deallocated이면 → skip, debt 없음.
  3. record_lsa <= page_lsa면 → skip/unfix.
  4. record가 더 새로우면 → callback.
  5. page LSA를 설정하고 DIRTY로 표시한다.
  6. 모든 exit에서 release한다.

일반화하지 말 것

  • page gate → 모든 callback side effect가 idempotent
  • recovery mode → ordinary allocation bypass
  • temporary-page 규칙 → permanent-page 규칙
  • checkpoint 성공 → crash-redo proof
  • backup accepted → home-page/DWB recovery proof
