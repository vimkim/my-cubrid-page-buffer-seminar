Pinned: f799e05Core 동작 6개Evidence-aware

첫머리에 제시할 contract

Logical identity + access intent → resident byte + page latch + 기록된 fix debt → 대응하는 unfix까지 빌려 쓰는 PAGE_PTR.

이 Module은 logical locking, record validation, recovery logging, page LSA 설정, dirty marking, caller cleanup까지 대신 완료하지 않습니다.

1–3 · 올바르게 빌려 쓰기

  1. Object: VPID → BCB ↔ frame → PAGE_PTR, global fcnt, per-thread holder.
  2. Acquire/release: hit와 miss의 준비 경로는 하나의 ownership postcondition으로 합류하며, 성공할 때마다 release debt 하나가 생깁니다.
  3. Caller: logical lock, validation, 변경, logging, page LSA 설정, dirty marking을 수행하고 모든 exit에서 정리합니다.

4–6 · 안전하게 전파하고 변경하기

  1. Flush: 복사된 generation G, WAL gate, DWB/direct-write boundary, 동시에 일어나는 G+1 re-dirty.
  2. Replace: policy보다 eligibility를 먼저 봅니다. unfixed라는 사실만으로는 부족합니다.
  3. Defend: Interface, owner, invariant, negative path, caller impact, verification seam을 근거로 방어합니다.

혼동하면 안 되는 네 쌍

  • Fixed와 resident는 같은 뜻이 아닙니다.
  • Dirty와 durable은 같은 뜻이 아닙니다.
  • Unfix와 flush는 같은 동작이 아닙니다.
  • Eviction과 deallocation은 같은 동작이 아닙니다.
