Domain과 search policy

free BCB가 없을 때의 흐름

Allocator exit

  1. invalid/free BCB로 성공
  2. eligible LRU victim으로 성공
  3. direct reservation 후 성공
  4. revocation 후 retry
  5. interrupt/shutdown
  6. timeout
  7. daemon 없이 synchronous flush/search
  8. 명시적인 no-buffer error

Direct victim 규칙

assignment는 reservation이다.

  1. producer가 eligibility를 확인한다.
  2. consumer가 나중에 lock/revalidate한다.
  3. 사이에 fix가 하나라도 들어오면 assignment를 revoke한다.
  4. allocator가 다른 candidate를 요청한다.

Generation 규칙

post-flush는 현재 resident state를 다시 확인한 뒤에만 assign할 수 있다. copied G의 flush가 끝나도 resident G+1이 DIRTY면 reuse 허가가 아니다.

근거 없이 강화하지 말 것

  • queue priority → starvation freedom
  • daemon loop → stable cadence
  • AOUT structure → active 2Q default
  • reuse counter → 실제로 관찰한 eviction
  • victim hint → eligibility proof
