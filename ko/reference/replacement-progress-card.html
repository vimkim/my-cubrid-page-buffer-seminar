Replacement progress

search와 coordination이 progress를 만들지만, 보호된 상태에서 eligibility를 확인해야만 frame을 reuse할 수 있다.

Pinned: f799e05취소 가능한 reservationfairness 정리 없음

“Private domain”의 의미

세션/worker는 private-list 번호를 빌리고 thread는 이를 private_lru_index에 들고 다닌다. BCB는 세션 owner가 아니라 현재 LRU/zone 하나만 저장한다. 여러 세션이 같은 private LRU를 공유할 수 있고, 세션이 해제되어 assignment를 release해도 BCB를 비우거나 옮기지 않는다.

마지막 unfix의 placement

Ordinary movement는 global fcnt가 0일 때만 시작한다. 첫 placement는 private LRU1 top 또는 shared LRU2 middle이다. Domain mismatch 또는 hot+old인 private member는 BCB mutex를 유지한 채 private → VOID → shared middle로 이동한다.

Domain과 search policy

Scan depth와 list count를 구분할 것

수량

  • N개 BCB/frame pair, startup invalid count = N
  • L = S + P개의 persistent LRU object
  • P의 상한은 1,000이 아님. auto = MAX_NTRANS + 50, explicit max = 4,050
  • Private Q: LRU1 5%, LRU2 5%
  • Shared target: 기본 LRU1 40%, LRU2 5%
  • Private Q 하나 ≤ min(5,000, N/2)

비용

  • invalid head: O(1)
  • known LRU link edit: O(1) + demotion
  • private assignment: O(P)
  • quota pass: O(T + S + P + demotion)
  • shared 선택: amortized O(1), periodic O(S)
  • shared placement/migration: amortized O(1 + D), periodic O(S + D)
  • hit registrar / move predicate: O(1)
  • resident fix: wait 전 O(hash chain H + holder list R)
  • unfix: O(R + waiter scan W) + placement work
  • selected-list scan 1회: LRU3 BCB visit 최대 1,000개
  • helper 전체: O(demotion + bounded scan)
  • cross-private discovery: all-P scan 없음

free BCB가 없을 때의 흐름

Allocator exit

  1. invalid/free BCB로 성공
  2. eligible LRU victim으로 성공
  3. direct reservation 후 성공
  4. revocation 후 retry
  5. interrupt/shutdown
  6. timeout
  7. daemon 없이 synchronous flush/search
  8. 명시적인 no-buffer error

adjust_age

실제로 실행된 pgbuf_adjust_quotas() pass만 이 epoch을 증가시킨다. 100-ms daemon call도 gate에서 return할 수 있다. BCB 하나는 epoch마다 현재 LRU에 hit를 최대 하나만 더하고, 다음 pass는 ATOMIC_TAS_32로 list hit를 가져오면서 reset한다.

Direct victim 규칙

assignment는 reservation이다.

  1. producer가 eligibility를 확인한다.
  2. consumer가 나중에 lock/revalidate한다.
  3. 사이에 fix가 하나라도 들어오면 assignment를 revoke한다.
  4. allocator가 다른 candidate를 요청한다.

Generation 규칙

post-flush는 현재 resident state를 다시 확인한 뒤에만 assign할 수 있다. copied G의 flush가 끝나도 resident G+1이 DIRTY면 reuse 허가가 아니다.

AOUT 상태와 dormant admission

Pinned 상태: startup이 data_aout_ratio = 0을 강제하므로 ghost storage를 할당하지 않습니다. Historical CBRD-20741은 assertion/core를, CBRD-21135는 root cause를 모르는 동안 AOUT을 끄기로 한 결정을 기록합니다. 안전하게 활성화된다면 private AOUT miss는 middle, same-private refault는 top, other-private refault는 shared middle로 들어갑니다. 이는 dormant source branch이며 측정된 성능 향상이 아닙니다. 되살리기 전에 invariant를 고치고 stress test하며 single global Aout_mutex를 측정해야 합니다. Forced-zero line만 지우는 것은 fix가 아닙니다.

근거 없이 강화하지 말 것

  • queue priority → starvation freedom
  • daemon loop → stable cadence
  • AOUT structure → active 2Q default
  • reuse counter → 실제로 관찰한 eviction
  • victim hint → eligibility proof
