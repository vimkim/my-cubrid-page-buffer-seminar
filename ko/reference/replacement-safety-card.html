한 문장으로 설명하는 BCB identity

Stable slot, one current VPID: BCB/frame address는 A를 나타내다가 detach된 뒤 B에 쓰이는 식으로 serial reuse되며, 동시에 두 resident page identity를 나타내지 않습니다.

policy보다 먼저 확인할 eligibility

Hard predicate

  1. identity가 여전히 candidate와 일치합니다.
  2. fix owner나 transient right가 남아 있지 않습니다.
  3. DIRTY 또는 FLUSHING generation debt가 남아 있지 않습니다.
  4. 충돌하는 waiter가 없습니다.
  5. BCB protection 아래에서 모든 condition을 다시 통과합니다.

Policy input

  • LRU placement와 victim zone
  • private domain과 shared domain
  • quota와 “another chance” decision
  • candidate queue와 hint
  • 취소할 수 있는 direct assignment

policy는 eligible frame의 순위를 정할 뿐, 통과하지 못한 eligibility를 고치지 않습니다.

빠르게 떠올릴 네 가지 counterexample

  • fcnt == 0 + DIRTY → 아직 propagate하지 않은 debt
  • fcnt == 0 + FLUSHING → in-flight identity
  • fcnt == 0 + waiter → pending right
  • lock 전에 모두 clear → observation이 stale일 수 있음

동작을 구분하는 verb test

  • Unfix: ownership debt 하나를 갚습니다.
  • Flush: copied generation 하나를 propagate합니다.
  • Victimize: 안전한 frame을 detach해 reuse할 수 있게 합니다.
  • Invalidate: coherence를 위해 mapping을 제거하거나 거부합니다.
  • Deallocate: logical storage ownership을 끝냅니다.
