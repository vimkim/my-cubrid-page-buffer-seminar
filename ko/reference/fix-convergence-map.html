Normal fix convergence map

Caller intent와 준비 경로를, 두 경로가 공유하는 ownership postcondition과 구분해서 보세요.

Pinned: f799e05Normal mutex pathEvidence-aware

준비 경로는 둘, contract는 하나

Caller intent

  1. Fetch mode: allocation/residency에 대해 caller가 알고 있는 조건입니다.
  2. Latch mode: 허용할 content access 방식입니다.
  3. Condition: conflict가 생기면 기다릴지 거절할지 정합니다.

Grant 없이 NULL을 반환했다면 unfix debt도 생기지 않습니다.

Resident hit

  1. Hash에서 일치하는 candidate를 찾습니다.
  2. 그 candidate의 BCB를 lock합니다.
  3. 보호를 확보한 상태에서 VPID를 다시 확인합니다.
  4. 재사용 가능한 slot이 다른 page에 rebound되었다면 chain 탐색을 다시 시도합니다.

Cold miss

  1. 먼저 등록하여 해당 VPID의 load owner가 됩니다.
  2. 아직 publish하지 않은 provisional BCB를 확보해 배정합니다.
  3. OLD_PAGE라면 DWB, 그다음 volume에서 읽고, NEW_PAGE라면 초기화합니다.
  4. 확인하고 grant한 뒤 publish하고 load lock을 해제합니다.
  5. Waiter를 깨웁니다. 각 waiter는 다시 시도해 자신의 debt를 얻습니다.

공통 success postcondition

  1. 요청한 VPID가 resident입니다.
  2. 요청한 latch가 grant되었습니다.
  3. Global fcnt와 thread holder에 이 grant가 반영되었습니다.
  4. 빌린 PAGE_PTR에는 대응하는 unfix 하나의 debt가 있습니다.
