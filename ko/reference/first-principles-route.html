3시간 경로: 처음부터 이해하는 page buffer

기본 프로그래밍 지식에서 시작한다. 각 개념에서 무엇인지, 왜 필요한지, 없으면 무엇을 대신 마련해야 하는지, 구체적인 예, 실제 코드를 연결한다. 이 경로는 선택한 핵심 동작을 다루는 3시간 구성이다. 전체 다회차 curriculum도 계속 이용할 수 있다.

자료구조 구간에서 이어 보기

Page identity, frame, BCB를 먼저 구분하고 초기화를 본다. 이어서 private/shared domain과 final-unfix의 첫 배치 경로를 확인한다.

  • Private/shared LRU
  • Final-unfix 소스 경로

CUBRID 교체 구간에서 이어 보기

Dirty/fixed/clean 후보 예시에서 시작하고 다섯 함수의 miss 경로를 추적한다. Exact LRU와 조건부 zone 이동을 비교한다. List 선택과 보호 아래 재검사에서 frame 재사용까지 연결한다.

  • Miss 소스 경로
  • Exact-LRU 반례
  • Domain 선택
  • 보호 아래 재검사

Daemon 구간에서 이어 보기

Daemon과 boot gate를 정의한다. Page-flush와 post-flush, 이어서 maintenance와 flush-control을 추적한다. 없을 때의 영향은 fallback 경로와 함께 읽는다.

  • Cleaning과 완료 처리
  • 호출과 전달
  • Maintenance와 pacing
  • Post-flush 소스 경로
  • Maintenance 소스 경로
  • Flush-control 소스 경로

예제와 화살표를 읽는 방법

코드 화살표는 명시한 분기에서 확인한 직접 caller → callee 관계다. 가지가 있는 그림 전체가 동시에 하나의 stack인 것은 아니다. Queue 전달은 실행 context를 건넌다. 소스 경로는 debugger capture가 아니다. 교과서 예제는 추상 모델이고, DB 예제는 조건을 한정한 구성 상태다. 측정 결과나 아주 작은 pool 구성이 지원된다는 주장이 아니다.

오해정확한 설명과 근거
“LRU는 정확한 마지막 접근 순서다.”CUBRID에는 domain, zone, 조건부 이동이 있다. 전역 exact-LRU 순위 하나를 유지하지 않는다. 근거 →
“Private page는 내 session만 접근한다.”같은 pool 안의 배치/quota 영역이다. 접근 보호는 별도다. 근거 →
“BCB array와 LRU array는 같은 것이다.”하나는 frame 제어 정보를, 다른 하나는 그것을 연결하는 list descriptor를 담는다. 근거 →
“Fix count가 0이면 바로 재사용한다.”Dirty/flushing, waiter, flag, lock과 보호 아래 재검사가 남아 있다. 근거 →
“Unfix, flush, eviction, commit은 같은 일이다.”각각 사용 반납, image 전파, resident mapping 제거, transaction 완료다. 근거 →
“Post-flush가 page를 다시 쓴다.”BCB pointer를 받아 상태 처리를 마친다. Queue 전달은 비동기 경계다. 근거 →
“Flush-control은 write 이전 허가다.”참여 writer는 OS write 성공 후 credit을 소비한다. 근거 →
“Flush 완료면 지금 page는 clean이다.”더 최근 generation은 dirty일 수 있다. DWB 수락과 home-page 완료도 다르다. 근거 →
“CUBRID는 항상 2Q/AOUT를 실행한다.”고정 리비전의 parameter tuning은 AOUT를 강제로 끈다. 남아 있는 코드가 활성 동작은 아니다. 근거 →
“Maintenance가 backup direct victim을 보장한다.”VS-20의 loop는 이 리비전에서 본문을 건너뛴다. 다른 공급자는 남아 있으며 runtime starvation을 증명한 것은 아니다. 근거 →
“1,000 제한은 할당 전체의 상한이다.”선택한 list 하나의 BCB 방문 상한이다. 다른 list 시도와 사전 zone demotion은 별도다. 근거 →
“Miss는 물리 disk I/O이고 hit는 기다리지 않는다.”하위 cache가 읽기를 처리할 수 있고, resident page도 latch를 기다릴 수 있다. 근거 →

없는 page 하나를 처음부터 끝까지 설명하기

P 요청 → resident 조회 → 없으면 frame 확보 → invalid 자리가 우선이고, 없으면 domain과 적격 후보 선택 → 보호 아래 재검사 → 이전 mapping 제거 → P 준비 → 접근 권한 획득 → 사용 후 unfix. 변경이 남으면 WAL 순서를 지키는 cleaning이 이후 재사용을 준비할 수 있다. Flush 완료 자체가 eviction은 아니다.
