커리큘럼 안내

하나의 메커니즘에서 모듈 전체로

아래의 개념 순서로 진행합니다. 진행 순서가 바뀌어도 강의 식별자는 유지합니다. 각 강의는 설명, source tracing, 함께 생각하기, 질문으로 구성됩니다.

01

기초 모델

  1. Lecture 1 — Module 경계와 page journey페이지 획득부터 변경, 전파, frame 재사용까지 이어지는 흐름을 살펴봅니다. 각 전이의 책임과 근거를 연결합니다.
  2. Lecture 2 — 객체와 독립적인 상태 축Identity, resident storage, 빌려 쓰는 접근 권한, ownership accounting은 같은 페이지의 서로 다른 측면을 설명합니다.

02

획득과 소유권

  1. Lecture 3 — Hit와 miss의 합류Hit와 miss는 접근을 준비하는 과정이 다릅니다. 두 경로가 identity 확인과 caller의 ownership contract로 합류하는 과정을 살펴봅니다.
  2. Lecture 4 — Fix debt와 releaseFix가 성공할 때마다 release 책임이 하나 생깁니다. Global ledger와 thread별 ledger로 nested ownership을 추적합니다.
  3. Lecture 4A — Holder의 구조와 수명Thread의 anchor와 재사용되는 holder entry가 반복 BCB 접근을 ownership accounting 및 탐색 비용과 연결합니다.

03

변경과 durability

  1. Lecture 5 — Caller의 correctness와 logged mutationFix 성공으로 접근 권한을 얻어도 logical locking, validation, logging, dirty publication과 cleanup은 caller의 책임으로 남습니다.
  2. Lecture 6 — Flush generation과 WAL 순서완료된 flush는 특정 복사본에 해당합니다. 새 resident 변경, checkpoint 선택, persistence를 각각 구분해 살펴봅니다.
  3. Lecture 6A — Page-buffer daemon의 lifecycle네 background 역할은 thread lifecycle을 공유하지만, recovery gate가 열린 뒤 수행하는 작업은 서로 다릅니다.
  4. Lecture 6B — Page-flush와 post-flush handoffAllocator pressure가 candidate 선택, generation 제출, 보호 아래 재확인, allocator wakeup으로 이어집니다.
  5. Lecture 6C — Replacement maintenance와 I/O pacingQuota maintenance와 write 이후 token control은 서로 다른 상태와 timing policy를 통해 이후 진행을 조절합니다.

04

교체와 진행

  1. Lecture 7 — Victim eligibility와 frame 재사용Missing page에는 저장 공간이 필요합니다. Frame 재사용에는 replacement 선호도뿐 아니라 보호 아래에서 확인한 안전 조건이 필요합니다.
  2. Lecture 12 — Replacement 상태와 진행하나의 BCB/frame pair가 admission, cooling, victim 확인을 거쳐 다른 identity에 연결되는 과정을 살펴봅니다.
  3. Lecture 12B — Private LRU index와 선택계속 존재하는 list descriptor, session이 빌리는 index, BCB의 소속, victim search에는 각각 다른 수명과 규칙이 있습니다.
  4. Lecture 12A — 비활성 AOUT admission history소스에는 AOUT ghost admission metadata가 남아 있지만, 기준 revision의 parameter tuning은 그 동작을 비활성화합니다.

05

동시성

  1. Lecture 9 — Latch queue와 grant 결과Pending request, latch grant, holder accounting 완료는 대기 경로에서 서로 다른 사건입니다.
  2. Lecture 10 — Promotion과 page-state 연속성전용 promotion은 기존 ownership을 변환합니다. 성공적인 handoff와 실패 결과에 따라 caller가 유지할 수 있는 정보가 달라집니다.
  3. Lecture 11 — Ordered refix와 재검증순서를 지키면 multi-page 대기의 순환을 끊을 수 있습니다. Page를 놓았다 다시 얻는 동안 이전 관측이 무효가 될 수도 있습니다.

06

복구와 특수 경로

  1. Lecture 13 — Log buffer와 data-page redoLog storage와 data-page residency는 담당 owner가 다릅니다. Page LSA는 복구할 record를 skip 또는 apply하는 판단과 연결합니다.
  2. Lecture 14 — Startup과 shutdown의 의존 관계Initialization, recovery gate, finalization의 순서는 각 resource를 마지막으로 사용하는 주체를 고려해야 합니다.
  3. Lecture 15 — 특수 접근 경로의 contractPointer type이 비슷해도 ownership, protection, 허용 작업, cleanup 책임은 다를 수 있습니다.
  4. Lecture 16 — 실패 시 cleanup과 근거소스에서 확인한 return은 조사의 출발점입니다. 남은 상태, retry 동작, 영향 범위를 통해 결론을 뒷받침합니다.

07

Maintainer 통합

  1. Lecture 8 — 변경 영향과 검증변경 검토에서는 interface 동작, 상태의 owner, invariant, 실패 시 cleanup, caller 영향, 검증을 연결합니다.
  2. Lecture 17 — Maintainer 통합과 technical defense일관된 page journey를 바탕으로 source trace, 반례, 진단, 근거 있는 변경 계획을 연결합니다.

08

다른 엔진과의 비교

  1. Lecture 18 — 세 buffer pool의 책임 분담CUBRID, PostgreSQL, InnoDB는 공통된 안전 문제를 서로 다른 ownership 및 cleanup 메커니즘으로 해결합니다.
  2. Lecture 18A — 엔진별 replacement policyAdmission, 재사용 이력, victim 선택, dirty-page 진행을 공통 질문으로 삼아 소스에 근거해 비교합니다.

강의 사이의 실습

소스 전이 하나를 추적해 owner와 invariant를 기록하고 반례를 예상합니다. 통합 워크숍에서 연결을 다시 확인합니다. Runtime evidence가 필요한 질문에는 되돌릴 수 있는 probe를 사용합니다.
