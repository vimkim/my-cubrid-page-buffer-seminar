반드시 다룰 여덟 가지 move

page 하나의 journey를 따라가며 model을 방어하기

1

Module boundary

성공한 fix는 무엇을 보장합니까? correctness를 위한 작업 가운데 여전히 caller나 다른 dependency의 책임인 것은 무엇입니까?

2

Page journey

VPID → fix → holder/latch → mutation/logging → DIRTY → flush → victim eligibility → BCB reuse를 순서대로 trace합니다.

3

Independent axis

residency, ownership, content-latch, dirty/flush state를 설명합니다. 서로 같은 뜻처럼 보이는 두 개념이 실제로는 다름을 보여 주는 조합 하나를 드세요.

4

Generation reasoning

개념상의 G와 G+1을 설명하고 page LSA와 구분한 뒤, DIRTY/FLUSHING의 네 조합을 모두 해석합니다.

5

Safe replacement

왜 fcnt==0만으로는 부족합니까? stable BCB slot 하나가 동시에 두 VPID를 나타내지 않으면서 시간에 따라 서로 다른 VPID를 나타낼 수 있는 이유는 무엇입니까?

6

Evidence-bounded concern

VS-11 또는 VS-12를 선택합니다. pinned source가 확인해 주는 사실과 reachability, surviving state, impact, current-branch status를 분리하세요.

7

Latch wait

BCB에 queued된 request, atomic tuple에 기록된 grant, resume한 thread의 holder를 구분합니다. fairness boundary도 명시하세요.

8

Document route

학습, 변경, debug, source/invariant 찾기, evidence status 확인, rehearsal은 각각 어디에서 시작해야 합니까?
