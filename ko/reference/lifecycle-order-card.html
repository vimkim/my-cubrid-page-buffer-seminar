Page buffer lifecycle

work를 허용하기 전에 dependency를 만들고, service를 파괴하기 전에 그 service의 consumer를 모두 멈춘다.

Startup/shutdown order

Structural invariant

  • daemon destruction/pool finalization 후에는 어떤 daemon도 pool을 만지지 않는다.
  • log_final()은 page propagation이 가능한 상태에서 실행된다.
  • DWB는 마지막 page-write dependency가 끝날 때까지 유지된다.
  • file management는 page buffer finalization이 끝날 때까지 유지된다.

Identity owner boundary

  • file/disk/recovery가 logical allocation을 결정한다.
  • caller가 special fetch semantics를 선택한다.
  • page buffer가 resident coherence를 보장한다.
  • raw overwrite 전에 flush/invalidation이 필요하다.

Startup 순서 요약

  1. lock manager
  2. page buffer pool
  3. file manager
  4. DWB/metadata ready
  5. daemon을 생성하되 gate한다.
  6. log recovery
  7. flush work를 허용한다.

Shutdown 순서 요약

  1. vacuum/background work를 멈춘다.
  2. page buffer daemon을 파괴한다.
  3. pool이 살아 있을 때 log_final()을 실행한다.
  4. page propagation 후 DWB를 파괴한다.
  5. pgbuf_finalize()
  6. file-manager finalization
