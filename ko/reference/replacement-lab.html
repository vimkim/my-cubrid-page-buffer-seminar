교체 실험: 재사용, 교체 조건, 관리 비용

교육용 정책 trace, 소스 메커니즘, 별도로 기록한 native 실험을 구분해 비교한다.

무엇을 최적화하는가?

제한된 버퍼에서는 페이지 재사용 효과와 교체 관리 비용을 함께 봐야 한다. 페이지 적재 감소는 성능 개선의 원인을 설명할 수 있지만 그 자체가 성능 개선은 아니다. 같은 작업의 완료 시간과 read I/O를 따로 확인한다. YCSB/sysbench 결과는 검증한 워크로드와 조건에 한정해 주장하며 실제 고객 서비스 전반의 효과는 미확인이다. 통계 설계와 범용 측정 프레임워크는 별도 작업이다.

한 접근씩 따라가기

교육용 모델: 빈 버퍼, clean·교체 가능 페이지, miss마다 요청 페이지 적재, prefetch·bypass 없음. Miss는 모델의 적재 수이며 물리 disk I/O가 아니다. U/S 표시는 지정한 접근 순서이며 CUBRID 동시 실행이 아니다.

반례로 적용 범위를 확인하기

프레임 3개에서 ABCD 순환은 LRU miss 12번을 만든다. 목록의 중간도 안전한 피난처가 아니다. MRU는 이 순서에서는 유리하지만 AB 이후 CD만 반복하면 다시 쓰지 않는 A/B를 보존해 불리하다. LRU로 첫 ABCD를 처리한 D C B 상태에서 다음 A를 위해 D를 내보내면 B/C를 남긴다. 이는 그 중간 상태의 국소 선택이며 처음부터 MRU로 실행한 경로와 다르다. 첫 D 적재 전에는 D가 거주하지 않는다.

승격과 경계 재조정

소스 설명용 구성 상태: 하나의 양방향 LRU, zone 1 임계치 2, zone 1+2 임계치 4. 같은 list의 E를 승격하며 경합·직접 할당·private/shared 이동은 제외한다. 실행 캡처가 아니다.

노드 하나의 이동이 전환 전체는 아니다

BCB가 주어지면 flags와 배열 index를 통한 zone·list 조회는 O(1)이고 알려진 노드의 연결 변경도 O(1)이다. VPID로 BCB를 찾는 hash chain 검색은 별도다. 승격 전체에는 LRU mutex, flags·개수·후보 hint 갱신과 CAS 재시도, 경계 재조정이 포함된다. BCB k개를 조정하면 순회 작업은 O(k)다. 이는 실행 시간 측정이나 상각 O(1) 증명이 아니다. 강등은 노드를 옮기지 않고 zone과 경계만 바꿀 수 있다. Zone 3에서 top으로 바로 승격할 수 있으므로 3 → 2 → 1은 필수 승격 순서가 아니다.

Quota와 실제 리스트 길이는 다르다

Private 보호 zone 각각의 임계치는 floor(quota × 0.05)이며 quota는 5000과 전체 pool 절반으로 제한된다. N=4000, 실제 리스트 길이=4000, quota=2000이고 보호 zone이 차 있다면 100/100/3800개다. 이 구성 예시의 2.5%/2.5%/95%를 고정 비율로 읽지 않는다. 고정 리비전은 parameter tuning에서 AOUT를 강제로 끈다. 남아 있는 삽입 분기를 활성 2Q 동작으로 설명하지 않는다. 새 페이지는 보통 최종 unfix 때 private top으로 들어가지만 hit는 zone·age·domain 조건을 따른다.

우선순위, 재사용, flush는 별개다

Dirty와 latch 상태는 독립된 축이다. Fix 중에는 frame을 재사용할 수 없다. Unfixed만으로 충분하지 않으며 dirty/flushing·waiter·flags·보호 아래 재검사가 남는다. Dirty이고 다른 flush가 진행 중이지 않을 때:

  • Read latch 중: safe flush 가능.
  • 다른 스레드의 write latch: flush 요청을 남기며 동기 호출자는 대기.
  • Write holder 자신: fix를 유지한 채 safe flush 가능.

소스로 확인한 조건이며 새로운 동시 실행 실험 결과는 아니다.

실제 CUBRID 실험

관측 조건: 고정 소스 + 실험용 관측·maintenance 제어, debug SERVER_MODE, 4096 frames, 실제 할당 페이지, 순차 READ fix/unfix. 준비 후 maintenance를 mutex로 고정하고 flush daemon은 유지했다. 각 요청의 VPID와 일치하는 이벤트만 hit/miss로 센다. Debug metadata 접근은 별도다.

순환 사례의 마지막 private LRU: quota 2048, 임계치 102/102, zone 1/2/3 = 102/102/3889, 실제 list 길이 4093. 전체 4096 frames와 해당 list 길이는 다르다. 약 2.49%/2.49%/95.02%는 이 관측의 비율이며 고정 상수가 아니다. 대조군의 최종 quota는 1995이고 zone은 99/99/1850이었다. 반복 실행에서는 quota 1990, 같은 zone 크기였으며 hit/miss 결과도 같았다. 준비 과정의 활동량과 조정 시점도 영향을 준다.

이 조건에서 순환 all-miss가 실제로 관측됐다. 모든 CUBRID 실행이나 SQL 성능으로 일반화하지 않는다. READ_FROM_DISK는 엔진의 읽기 경로이며 물리 장치 miss의 증거가 아니다. Flush/latch 동시성 조건은 별도 소스 설명이다.
