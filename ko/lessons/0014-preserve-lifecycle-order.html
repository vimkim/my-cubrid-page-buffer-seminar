01 · Identity ownership

Logical lifecycle 결정이 먼저, cache coherence가 다음이다

결정OwnerPage-buffer의 후속 동작
Logical page identity를 allocate/deallocateFile/disk/recovery protocol요청에 따라 resident mapping을 materialize, reject, invalidate한다.
NEW_PAGE 또는 recovery fetch mode 선택Allocation/recovery 지식을 가진 caller그에 맞는 resident-byte initialization/validation contract를 적용한다.
Raw/bypass overwriteFile/disk owner외부 byte가 교체되기 전에 필요한 cached mapping을 flush/invalidate한다.

Invalidation은 cache-coherence를 지키기 위한 결과다. Storage의 logical allocation 여부를 스스로 결정하지 않는다.

대표 source: allocation ordering은 file_manager.c:5420–5590, bypass reset/coherence는 disk_manager.c:721–811.

02 · Dependency graph

Pool은 생성 주체와 뒤늦게 사용하는 consumer 사이에 있다

Startup은 작업을 허용하기 전에 dependency를 만들고, shutdown은 pool을 제거하기 전에 consumer를 멈춘다.

두 가지 structural rule: finalize된 pool에는 어떤 daemon도 접근하면 안 된다. Page를 propagate할 수 있는 log finalization 동안에는 pool과 write dependency가 살아 있어야 한다.
03 · Startup과 recovery

File 사용 전에 pool을 만들고 recovery 후에 flush 작업을 허용한다

  1. Lock manager를 initialize한다.
  2. pgbuf_initialize()를 호출해 pool, hash, list, frame, holder anchor를 만든다.
  3. Pool이 생긴 뒤 file management를 initialize한다.
  4. Restart 중에는 page-buffer/DWB daemon을 만들기 전에 DWB/module metadata를 recover한다.
  5. Task가 gated된 상태로 daemon object를 만든다.
  6. 살아 있는 pool을 통해 log recovery를 수행한다.
  7. Recovery가 끝난 뒤에만 flush daemon을 enable한다.

“Daemon이 존재한다”와 “daemon이 작업할 수 있다”는 서로 다른 lifecycle state다. Gating은 background flush policy가 끝나지 않은 restart recovery와 race하는 것을 막는다.

Verified mechanism: transaction-table setup log_tran_table.c:468–512, boot/recovery boot_sr.c:1974–2801, daemon gate page_buffer.c:16996–17136.

04 · Normal shutdown

사용 중인 resource를 finalize하기 전에 producer부터 멈춘다

  1. Vacuum/background ownership을 멈춘다.
  2. 이후 pool state에 접근할 daemon이 없도록 page-buffer daemon을 destroy한다.
  3. Page buffer가 아직 살아 있을 때 log_final()을 실행한다. 마지막 log 작업에서도 page propagation이 일어날 수 있다.
  4. 필요한 page propagation이 끝난 뒤에만 DWB를 destroy한다.
  5. Transaction-table teardown 중 page-buffer pool을 finalize한다.
  6. Pool이 더 이상 필요로 하지 않을 때 file management를 finalize한다.

Verified mechanism: shutdown boot_sr.c:3055–3113, daemon destruction page_buffer.c:17244–17255, transaction-table teardown log_tran_table.c:580–594.

05 · Counterexample

그럴듯한 순서 변경이 dependency를 깨뜨린다

잘못된 변경깨지는 dependencyFailure 형태
Daemon destruction 전에 pgbuf_finalize()Background consumer가 pool보다 오래 산다.Daemon이 finalize된 list, frame, queue, lock을 dereference할 수 있다.
pgbuf_finalize()를 log_final()보다 먼저 호출뒤늦은 log finalization이 page-propagation service를 잃는다.마지막 log 작업이 필요한 page를 안전하게 fix/flush할 수 없다.
Recovery 완료 전에 flush daemon enableBackground policy가 recovery ownership과 race한다.끝나지 않은 recovery state가 일반 flush/replacement 작업에 노출된다.
Invalidation 없는 raw overwrite외부 byte reset 후에도 cached identity가 남는다.Reader가 storage와 맞지 않는 stale resident byte를 볼 수 있다.
06 · Restart failure cleanup

Error cleanup에서도 같은 dependency 방향을 지킨다

Restart가 실패했다고 해서 임의의 역순 destruction이 허용되는 것은 아니다. 먼저 작업을 disable하고, 안전한 seam에서 daemon/DWB owner를 destroy하며, 필요한 service가 남아 있을 때 logging을 finalize한 다음 pool과 file dependency를 teardown한다.

정확한 branch는 normal shutdown과 다르지만 invariant는 같다. Consumer는 앞으로 호출할 수 있는 resource보다 오래 살아서는 안 된다.

Verified mechanism: restart-error cleanup은 pinned boot_sr.c:2740–2800에 있다.
