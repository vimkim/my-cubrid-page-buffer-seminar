01 · seam에서 시작하기

Module이 caller에게 무엇을 제공하는지 먼저 말합니다

page-buffer Module은 logical page identity와 access intent를 받아 resident bytes에 대한 임시 latched access를 제공합니다. 강력한 contract이지만, 이것만으로 caller의 logical operation이 끝나는 것은 아닙니다.

정상 fix가 성공하면 VPID가 resident BCB/frame에 연결되고, 요청한 page latch가 grant되며, ownership debt 하나가 기록됩니다. 그리고 matching unfix 전까지 PAGE_PTR를 빌려줍니다.

reasoning guardrail: contract를 “memory에서 page를 가져온다”라고만 줄이지 마세요. 그렇게 말하면 identity validation, miss materialization, latch grant, fix accounting, pointer lifetime, 그리고 caller가 여전히 책임져야 할 작업이 모두 가려집니다.

Canonical 설명: Contract and Objects. Pinned source: page_buffer.c:2260–2685, 6277–6634, 3062–3201.

02 · 명사를 섞지 않기

“page”라는 한 단어 뒤에는 서로 다른 여섯 객체가 있습니다

call flow가 아니라 관계와 lifetime을 보여 주는 그림으로 읽으세요.

VPID는 logical page의 이름입니다. 재사용되는 BCB는 현재 resident인 identity를 기록하고, 재사용되는 frame을 가리킵니다. PAGE_PTR는 그 bytes를 잠시 빌려 보는 view일 뿐입니다. Global fcnt와 현재 thread의 holder는 아직 갚지 않은 fix debt를 기록하는 두 ledger입니다.

외워 둘 네 문장: fixed와 resident는 다릅니다. dirty와 durable도 다릅니다. unfix는 flush가 아니며, eviction은 deallocation이 아닙니다.

05 · evidence를 구분해 말하기

claim을 강화하기 전에 먼저 label을 붙입니다

이 guide는 여섯 claim level을 사용합니다. Interface contract, Verified mechanism, Implementation policy, Inference, Runtime observation, Historical evidence입니다. source에 보이는 branch 하나를 영구적인 API 약속으로 오해하거나, 한 번의 실험을 보편적인 runtime 사실로 확대하는 일을 막아 줍니다.

예: victim safety predicate는 pinned revision에서 Verified mechanism입니다. 정확한 LRU zone과 scan order는 Implementation policy입니다. 기존 실행에서 eviction이 없었다는 사실은 Runtime observation일 뿐, victim path가 실행될 수 없다는 증거가 아닙니다.

Evidence 용어: CONTEXT.md. 변경될 수 있는 candidate 상태: Evidence and uncertainty registry.

06 · Retrieval practice

page journey를 기억만으로 다시 구성합니다

문제

“CUBRID의 page-buffer Module은 무엇을 하며, maintainer는 어떤 page journey를 따라가고, 이후 실제 작업에서 팀은 이 문서들을 어떻게 활용해야 하나요?”

권장 답변 구조: boundary → 객체와 독립적인 axis → fix/release ownership → caller가 correctness 완성 → flush generation → policy보다 먼저 replacement eligibility → task와 evidence 경로.

할 일: 위 model을 그대로 베끼지 마세요. 두 axis를 혼동했을 때 생기는 결과 하나를 설명하고, claim 하나 이상에 evidence level을 붙이세요.

자동 검사는 vocabulary 포함 여부만 확인합니다. source-aware feedback을 받으려면 답을 chat에 붙여 넣으세요. 단순히 lesson을 읽었다는 사실이 아니라 이 teach-back 결과로 다음 lesson을 정합니다.
