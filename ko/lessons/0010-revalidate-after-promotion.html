01 · promotion 정의하기

READ holder가 WRITE protection을 요청한다

Latch promotion은 현재 thread가 resident page 하나에 가진 protection을 READ에서 WRITE로 바꾸려는 시도다. page-buffer protocol이 안전하게 upgrade할 수 있을 때 caller가 직접 전체 unfix/refix sequence를 수행하지 않게 하는 것이 목적이다.

Promotion은 transaction-level ownership을 주거나, B-tree search 결과를 마법처럼 보존하거나, 새로운 logical fix를 만들지 않는다. 같은 page-buffer ownership을 더 강한 byte protection 아래 다시 구성할 뿐이다.

02 · 네 가지 outcome

unfixed window를 여는 경로는 하나뿐이다

blocking 경로는 저장한 fix count를 queue로 옮기지만, 기다리는 동안 이 thread의 protection은 내려놓는다.

03 · Decision rule

“내가 유일한 fixer인가?”가 쉬운 경로를 결정한다

  1. 이 holder의 nested fix_count가 BCB의 global fcnt와 같으면 모든 fix가 이 thread의 것이다. 이미 기다리는 promoter가 없다면 latch mode를 in place로 바꿀 수 있다.
  2. 다른 reader가 있고 caller가 PGBUF_PROMOTE_ONLY_READER를 요청했다면 READ ownership을 release하지 않은 채 conditional failure로 끝난다.
  3. 다른 promoter가 이미 queue 맨 앞에 있으면 새 promotion도 conditional failure다. BCB 하나에는 promoter 하나만 기다릴 수 있다.
  4. 그 밖의 shared-reader 경로에서는 이 thread의 fix를 release하고 holder를 제거하며 promoter를 queue head에 넣고 WRITE를 기다린다.

Verified mechanism: pinned promotion은 page_buffer.c:2842–3050에 있다.

04 · Ownership accounting

저장한 fix count는 이동할 뿐 늘어나지 않는다

caller의 nested-fix count가 2라고 하자. Blocking promotion은 다음과 같이 동작한다.

  1. BCB의 global fcnt에서 2를 뺀다.
  2. 이 thread의 READ holder를 제거한다.
  3. 요청한 fix count 2를 queued promotion request와 함께 저장한다.
  4. grant되면 global tuple에 2를 복구하고 count 2인 새 WRITE holder를 만든다.

promotion 성공 전후에 caller가 갚아야 할 release는 4가 아니라 2다. wait 중에는 page pointer를 전혀 소유하지 않는다.

05 · Observation lifetime

pointer 값이 같아도 이전 지식은 복구되지 않는다

READ release와 WRITE grant 사이에 다른 owner가 page 내용을 바꿀 수 있다. 따라서 caller는 이전 hold에서 얻은 모든 결론을 버리거나 다시 구성해야 한다.

  • record pointer와 slot 위치,
  • free-space와 insertion 결정,
  • B-tree key range, separator, sibling/child 선택,
  • page header, generation/dirty 관찰값, related-page 관계,
  • 이전 page byte를 전제로 한 모든 access-method precondition.
흔한 bug 형태: promotion이 겉보기에는 같은 page pointer를 반환하므로 caller가 blocking 전에 계산한 slot이나 record pointer를 계속 사용한다. pointer equality는 이전 borrowed lifetime을 연장하지 않는다.
06 · Caller policy

Page buffer는 protection을 돌려주고 access method는 의미를 복구한다

Module은 latch/holder transition을 구현한다. semantic restart는 B-tree나 heap code의 책임이다. search를 반복하고 target record/slot을 확인한 뒤 mutation 전에 related-page 결정을 다시 구성해야 한다.

대표적인 B-tree caller는 promotion으로 의도한 경로를 보존할 수 없을 때 WRITE traversal로 전환하고 retry한다. 이는 access-method policy이지 promotion이 tree navigation을 보존한다는 일반적인 약속이 아니다.

대표 caller evidence: pinned B-tree restart point는 btree.c:28365–28393과 28638–28696이다.

07 · Retrieval 연습

nested blocking promotion을 audit한다

문제

Thread T가 nested READ fix 두 개를 hold하고 slot 7을 찾은 뒤 insertion 결정을 계산했다. 다른 reader도 page를 hold한다. T는 WRITE로 blocking promotion을 요청한다.

과제: wait와 success를 거치는 두 debt ledger를 trace하고 stale해지는 것을 나열하라. slot 7을 다시 찾아야 하는 이유를 설명하고 conditional failure 및 interruption과 대조하라.

답을 chat에 붙여 넣어 보자. debt conservation, stale observation, outcome classification, caller 책임을 확인한 뒤 Advanced 진도를 기록한다.
