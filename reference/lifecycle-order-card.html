Startup and shutdown order

Structural invariants

  • No daemon touches the pool after daemon destruction/pool finalization.
  • log_final() runs while page propagation remains available.
  • DWB survives until its final page-write dependency finishes.
  • File management survives until page-buffer finalization completes.

Identity owner boundary

  • File/disk/recovery decides logical allocation.
  • Caller chooses special fetch semantics.
  • Page buffer enforces resident coherence.
  • Raw overwrite requires flush/invalidation first.

Startup shorthand

  1. Lock manager
  2. Page-buffer pool
  3. File manager
  4. DWB/metadata ready
  5. Daemons created but gated
  6. Log recovery
  7. Flush work enabled

Shutdown shorthand

  1. Stop vacuum/background work
  2. Destroy page-buffer daemons
  3. log_final() with pool alive
  4. Destroy DWB after page propagation
  5. pgbuf_finalize()
  6. File-manager finalization
