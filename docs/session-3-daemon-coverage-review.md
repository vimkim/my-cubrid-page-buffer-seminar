## Initialization, ownership and teardown that the correction must teach

The server restart path recovers DWB pages, calls `pgbuf_daemons_init()`, creates DWB helpers, invokes log initialization/recovery, runs `boot_after_copydb`, then enables the flush gate. The four-role group attempts maintenance → page-flush → post-flush → flush-control creation; this is initialization order, not a page pipeline. Pool initialization precedes it, including quota/monitor structures, candidate storage and server queues. Returned pool-allocation errors use `pgbuf_finalize()` and abort that initialization. S1, S2, S4.

| Role | Task/context and role resources | Failure/absence behavior to explain |
| --- | --- | --- |
| Maintenance | Callable `pgbuf_page_maintenance_execute`, fixed looper, managed daemon entry; quota/monitor arrays and LRU mutexes are pool owned. | Disabled private quotas reject quota work, not thread creation. The pin's backup bodies are skipped (VS-20). |
| Page-flush | `pgbuf_page_flush_daemon_task` owns its performance tracker; callback looper reads the interval at each pause; candidate array and LRUs/monitor belong to pool. | Pointer absent permits synchronous requester fallback. A non-null pointer during recovery does not prove an open gate or fallback. |
| Post-flush | Callable `pgbuf_page_post_flush_execute`, increasing-wait looper; pool owns `flushed_bcbs` and direct-victim queues/BCB storage. | Missing daemon/full queue means local completion. An accepted enqueue remains CPU completion work and needs the BCB alive. |
| Flush-control | Task owns first-run timestamp and `retire()` cleanup; static token-bucket storage is initialized with mutex, condition and zero tokens before thread creation. | Mutex failure returns before publication. Condition-init failure returns after mutex init with no local mutex destroy. Initializer deletes the task without calling `retire()` and creates no daemon; unpublished bucket makes token acquisition a no-op. S9. |

Generic manager creation reserves a managed entry and can return `NULL` if entries are unavailable. The role initializers do not check that return or retire the unowned task on that path. Allocation/thread-construction exceptions also lack a local recovery wrapper in these seams. Thus “all four always exist” and “all initialization failures fully unwind” are unsupported. This is a **source-visible cleanup obligation**, not evidence of a reached failure or production leak: thread capacity is also planned by the daemon registry. S1, S3.

The execution context is claimed inside the new thread, marked `TT_DAEMON` with `LOG_SYSTEM_TRAN_INDEX`, and given its error context. On loop exit the worker stops/retires the execution context, then retires the task; flush-control finalizes its bucket here. Only after the thread ends does the destroying caller's `join()` return and the manager delete the daemon/clear its pointer. Correct chronology: **caller sets stop/wakes → running task finishes → worker retires context/task → thread exits → join returns → daemon pointer clears**. Pool/queue destruction follows later. S3, S5, S9.

Normal group destruction is maintenance → page-flush → post-flush → control, before `log_final()` and DWB/pool destruction. This keeps post-flush/control available while page-flush finishes. Restart-error cleanup additionally disables the gate, destroys page-buffer and DWB daemon groups, and then calls `log_final()`. Closing the gate blocks later task entries; it does not cancel an already executing helper. Page-flush's pressure loop and post-flush's drain loop do not poll the looper stop flag inside their work; locks, WAL, I/O and untimed token waits can delay returning to the outer stop check. No static wall-clock upper bound follows. A stop request alone also does not promise draining every queued item; do not add that guarantee without a shutdown producer/consumer proof. S1, S4–S7, S10.
