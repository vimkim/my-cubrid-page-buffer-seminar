Parameter evidence for [Session 3 daemon coverage review](session-3-daemon-coverage-review.md), work item 333, 2026-10-13. Engine authority is the locally verified CUBRID pin `f799e05d77d5300c6ea5753b4a6cc7caee6d8912` (`VERSION=11.5.0`). ## Conclusions that affect the review

1. **The page-flush configuration name is wrong in the live presentation.** The registered name is `page_flush_interval`, with deprecated alias `page_flush_interval_in_msecs`. `page_bg_flush_interval` is the internal naming vocabulary, not a registered user name. Both EN/KO `04-page-flush.html#trigger` and `03-daemon-architecture.html#experiment` use the unregistered name. The linked lifecycle research has the same inherited error. See [registered names](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/base/system_parameter.c#L259-L273), [definitions](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/base/system_parameter.c#L1806-L1829), and the unknown-name rejection at [7324–7328](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/base/system_parameter.c#L7324-L7338).
2. **Runtime mutability is almost entirely missing from the live chapters and spoken script.** The presentation teaches periods, zero, feedback and bypasses, but does not identify the DBA mechanism, registry flags, restart-only resources, next-read transitions or hidden/public distinctions. A name appears only for the incorrectly named interval. Neither the correct name nor `adaptive_flush_control`, `max_flush_size_per_second`, neighbor names, `data_buffer_flush_ratio`, `data_buffer_size`, or `num_private_chains` occurs in the spoken script. Correct role behavior is insufficient to classify the requested parameter/changeability dimension complete.
3. **`RELOADABLE` does not establish online operator mutability.** Pool size, LRU zone ratios, private-chain count and AOUT ratio have no `USER_CHANGE`; the normal SQL path rejects changes. Their consumers cache structures at initialization. Maintenance computes live quotas using those cached inputs; it does not reread these configuration values. [Validation](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/base/system_parameter.c#L7324-L7349), [reload filter](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/base/system_parameter.c#L6502-L6513), [pool cache](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/storage/page_buffer.c#L1713-L1743).
4. **AOUT is forced off at the pin.** Although `data_aout_ratio` is registered with range 0–3, `prm_tune_parameters()` forces it to 0 after parameter loading, with a comment referring to CBRD-20741. Do not advertise a restart setting as activating AOUT here. [Forced tuning](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/base/system_parameter.c#L9975-L9986), [tuning caller](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/base/system_parameter.c#L6255-L6275).
5. **The configured maximum participates only in non-adaptive pacing.** `adaptive_flush_control=yes` selects feedback plus a compiled 40 MiB/s floor; `max_flush_size_per_second` is read only in the `else` branch. It is not a demonstrated adaptive ceiling. [Branch](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/storage/file_io.c#L866-L889).
6. **DWB registration and active-resource change differ.** `double_write_buffer_size` and hidden block count accept an online registry update, but resources read them at creation. `dwb_recreate()` exists and has no source caller at this pin; the ordinary system-parameter setter does not recreate DWB. The local manual's dynamic table alone cannot establish active resizing. This is a static configuration boundary, not observed failure. See dependency table below.
7. **No local 11.5 manual is available.** The checked-out manual and the nearest release ref declare 11.4. Use the pin for behavior; use manual evidence only for individually compatible public names, units, table scope and administrator syntax. The manual contains behavioral discrepancies described below.

## Mutation mechanism and scope

Flag legend: S=`PRM_FOR_SERVER`; C=`PRM_FOR_CLIENT`; U=`PRM_USER_CHANGE`; H=`PRM_HIDDEN`; R=`PRM_RELOADABLE`; D=`PRM_DEPRECATED`; Z=`PRM_SIZE_UNIT`; T=`PRM_TIME_UNIT`; X=`PRM_DIFFER_UNIT`. Every bare identifier in a PRM_ID column or parameter row expands with the `PRM_ID_` prefix, for example `PB_BUFFER_FLUSH_RATIO` means `PRM_ID_PB_BUFFER_FLUSH_RATIO`. All daemon policy rows below are server-global, not session settings; none has `PRM_FOR_SESSION`. An online U setting uses the same DBA SQL/API path; hidden U means accepted internal setting, not recommended public operator contract.

The actual validated path is:

`SET SYSTEM PARAMETERS` -> `do_set_sys_params()` -> `db_set_system_parameters()` -> `sysprm_validate_change_parameters()` -> server request -> `xsysprm_change_server_parameters()` -> `sysprm_change_parameter_values()` -> `sysprm_set_value()`.
