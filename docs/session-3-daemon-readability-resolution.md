## Source decisions retained in the explanations

Creation attempts run maintenance → page-flush → post-flush → flush-control. Pool structures precede these attempts. Server restart performs DWB page recovery, group creation, DWB-helper creation, log initialization/recovery and `boot_after_copydb()` before opening the gate. The gate itself sends no wake. Returned pool errors finalize pool storage; unchecked manager `NULL` and creation exceptions are separately qualified. Control mutex and condition-init failures have different cleanup states. [Boot sequence](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/transaction/boot_sr.c#L2405-L2441), [group creation](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/storage/page_buffer.c#L17146-L17255), [bucket initialization](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/storage/file_io.c#L678-L740).

Stop/wake initiates shutdown. The worker retires its context and task, then exits; caller join returns afterward. Control task retirement finalizes its bucket. Pool/queue lifetime must encompass those worker accesses. This does not prove other writers are finished, cancel an I/O, guarantee a queue drain or bound join duration. The [worker sequence](https://github.com/CUBRID/CUBRID/blob/f799e05d77d5300c6ea5753b4a6cc7caee6d8912/src/thread/thread_daemon.cpp#L208-L245) corrects both prose and the shared visual.

Operator names come from registration, not internal `PRM_ID` spelling. Online DBA assignment changes registry values, not `cubrid.conf`. `USER_CHANGE` plus server authorization establishes acceptance; a consumer read establishes its effect point. Startup-cached structures, compiled constants and computed quotas/tokens are separate categories. The local 11.4 manual is used only where individually compatible; it is not a matched 11.5 behavior authority. Full units, aliases, ranges, default page-size dependence, hidden/nonhidden classifications, DWB resource caching and forced-inactive AOUT remain in the [parameter evidence](session-3-daemon-parameter-audit.md#mutation-mechanism-and-scope).
