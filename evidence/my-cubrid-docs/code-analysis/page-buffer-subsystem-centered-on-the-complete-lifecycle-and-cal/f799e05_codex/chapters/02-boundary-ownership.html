02. Module boundary와 object graph

학습 목표와 concrete scenario

page buffer의 책임과 caller/dependency seam, object owner와 lifetime을 구분한다.

질문: caller가 PAGE_PTR를 cache한 사이 ordered refix 또는 victim reuse가 일어나면 무엇이 stale해지는가?

직관: 한 page journey를 identity, ownership, concurrency, durability, release 순서로 따라가며 각 abstraction을 exact state와 guard로 교체한다.

Page buffer가 숨기는 것

heap / B-tree / recovery caller
        ↓ VPID + fetch/latch/condition
page_buffer: hash ─ BCB/frame ─ holder ─ LRU/flush
        ↓ read/write       ↓ WAL force       ↓ DWB
file_io                 log manager        double-write

page buffer는 residency, frame reuse, page latch와 physical I/O를 숨긴다. caller의 page type 의미, operation-level latch order, transaction lock, page mutation intent와 all-exit cleanup까지 자동으로 알아내지는 않는다.

Invariant: caller가 PAGE_PTR를 dereference하는 동안 그 thread의 successful fix가 살아 있어야 한다. ordered refix가 page_was_unfixed를 세우면 page-local pointer와 slot을 다시 계산해야 한다.

이 장의 요약과 다음 전환

Page buffer가 숨기는 책임과 caller에게 남는 책임을 분리했다. 다음 장에서는 VPID·BCB·frame·PAGE_PTR가 lifecycle phase마다 어떻게 전이하는지 본다.
