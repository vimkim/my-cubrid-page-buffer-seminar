04. pgbuf_fix(): lookup에서 borrowed pointer까지

학습 목표와 concrete scenario

pgbuf_fix의 fast hit, normal hit, miss owner/waiter, retry와 failure cleanup을 설명한다.

질문: 두 thread가 같은 cold VPID를 동시에 요청하면 어느 thread가 I/O와 publication을 소유하는가?

직관: 한 page journey를 identity, ownership, concurrency, durability, release 순서로 따라가며 각 abstraction을 exact state와 guard로 교체한다.

Complete hit/miss call flow

pgbuf_fix_release
 ├─ validate fetch/latch/condition; zero-wait may demote to conditional
 ├─ pgbuf_lockfree_fix_ro [OLD-family + unconditional READ]
 ├─ pgbuf_search_hash_chain
 │   └─ HIT: register fix → validate VPID → latch/holder
 └─ MISS: pgbuf_lock_page(VPID)
     ├─ waiter: wake → try_again (hash lookup)
     └─ owner: pgbuf_allocate_bcb
         → pgbuf_claim_bcb_for_fix
         → OLD: dwb_read_page → fileio_read → TDE decrypt
         → NEW: initialize without disk read
         → latch/holder → hash insert → unlock VPID

같은 VPID의 duplicate residency를 막는 serialization은 BCB latch가 아니라 VPID-keyed buffer lock이다. publication 이전 provisional BCB와 I/O failure cleanup은 miss owner 책임이다. 현 revision의 lock-free READ fast path에는 오래된 local note가 주장한 post-CAS VPID recheck가 없다. safety premise는 positive READ fcnt가 victimization을 막는다는 추론이며 별도 proof obligation이다.

Runtime. Isolated server start 뒤 first scan은 동일 checksum을 반환하며 Num_data_page_ioreads=38, heap OLD_NO_WAIT fixes를 보였다. 즉시 second scan은 ioreads 0과 heap OLD_PAGE_IN_PB fixes를 보였다. OS cache, exact VPID와 I/O source는 증명하지 않는다.

Error and pressure paths

  • OLD_PAGE_IF_IN_BUFFER miss는 I/O 없이 NULL이다.
  • conditional latch conflict는 PAGE_PTR 없이 실패하므로 unfix 대상도 없다.
  • no BCB/victim은 ER_PB_ALL_BUFFERS_DIRTY를 만든다.
  • DWB read error cleanup, TDE/DWB-slot early flush error, async-unfix flush error는 review candidates다. reachability와 indirect cleanup을 확인하기 전 “confirmed bug”로 말하지 않는다.
Heavy question. loader가 latch 획득 뒤 hash publish하는데 PostgreSQL/InnoDB는 I/O-in-progress mapping을 먼저 공개한다. 두 방식의 waiter semantics와 failure cleanup 비용을 비교하라.

이 장의 요약과 다음 전환

Fix는 lookup, load, latch와 holder를 묶는 ownership protocol이다. 다음 장에서는 latch compatibility와 unfix wakeup을 계산한다.
