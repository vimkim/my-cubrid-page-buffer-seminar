06. Heap, B-tree, recovery가 correctness를 완성한다

학습 목표와 concrete scenario

heap, B-tree, recovery caller의 ordering, mutation, all-exit cleanup 계약을 비교한다.

질문: B-tree parent/child와 heap page를 일부만 fix한 뒤 error가 나면 무엇을 dirty하고 무엇을 unfix해야 하는가?

직관: 한 page journey를 identity, ownership, concurrency, durability, release 순서로 따라가며 각 abstraction을 exact state와 guard로 교체한다.

ordered fix가 temporary unfix/refix하면 raw pointer 외의 page-local state도 stale해진다. watcher가 group/rank/VPID와 page_was_unfixed를 들고 있는 이유다. B-tree의 conditional sibling path는 기다리며 cycle을 만드는 대신 held pages를 풀고 higher-level restart를 택한다.

Covered PK query는 covered=100, noncovered=0, payload query는 noncovered=100과 heap fixes, update는 300 dirty calls와 heap HOLDER_DIRTY WRITE를 보였다. 동일 result만으로 exact call stack을 증명하지 않으므로 source caller trace와 함께 해석한다.
Heavy question. transaction lock이 row-level correctness를 보호해도 page latch가 필요한 이유를 physical bytes consistency와 logical visibility로 나누어 답하라.

이 장의 요약과 다음 전환

Caller가 page type, ordering, dirty와 cleanup을 책임한다. 다음 장에서는 수정된 page가 WAL과 storage를 거쳐 victim이 되는 흐름을 연결한다.
