09. 함수명이 아니라 responsibility를 비교한다

학습 목표와 concrete scenario

세 엔진을 identity, ownership, publication, caller, durability, recovery, error/resource pressure, configuration/observability와 performance라는 같은 축으로 비교한다.

질문: 함수 이름이 비슷하지 않아도 책임이 같을 수 있고, 이름이 비슷해도 비동치인 이유는 무엇인가?

직관: 한 page journey를 같은 열에 놓고, 직접 동치·부분 유사·비동치 판정을 분리한다.

PostgreSQL

ReadBuffer는 pinned Buffer handle을 주지만 ordinary content lock은 별도다. miss mapping은 I/O 전에 공개되어 readers가 BM_IO_IN_PROGRESS에 합류한다. caller는 pin/content lock/WAL balance를 소유하고 ResourceOwner가 error backstop이다. replacement는 clock sweep, torn-page defense는 core flush DWB 대신 full-page image/reinitialization 축이다.

MySQL/InnoDB

buf_page_get_gen은 nearest operation이지만 MTR이 필수 lifetime collaborator다. buffer-fix와 S/SX/X latch가 memo에 들어가 역순 release된다. clustered leaf가 row store라 CUBRID/PostgreSQL식 별도 heap page handoff가 없다. dirty page는 redo LSN/flush list를 거쳐 optional doublewrite/encryption/datafile path로 간다.
