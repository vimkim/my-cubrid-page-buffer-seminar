01. 먼저 다섯 질문을 고정한다

학습 목표와 concrete scenario

이 보고서의 scope, audience, 세 가지 reading path와 핵심 결론을 설명한다.

질문: 한 SQL reader가 cold heap page를 요청하면 어떤 subsystem들이 성공 전에 협력하는가?

직관: 한 page journey를 identity, ownership, concurrency, durability, release 순서로 따라가며 각 abstraction을 exact state와 guard로 교체한다.

Conclusion고정 source contract와 좁은 runtime 범위에서 source-closed 재구현·발표 준비가 되었다. 이는 일반 correctness나 performance parity 보장이 아니다.

pgbuf_fix(thread, vpid, fetch_mode, latch_mode, condition)는 disk read 함수가 아니다. 성공 전에 요청 identity가 올바른 resident bytes와 연결되고, frame이 교체되지 않으며, 요청 latch가 holder에 기록되었음을 만든다. 반환된 PAGE_PTR는 그 ownership 기간에만 유효한 borrowed pointer다.

다섯 질문은 VPID, BCB/frame/PAGE_PTR 소유권, latch conflict, WAL/data durability, unfix 후 재사용 조건을 분리한다.
