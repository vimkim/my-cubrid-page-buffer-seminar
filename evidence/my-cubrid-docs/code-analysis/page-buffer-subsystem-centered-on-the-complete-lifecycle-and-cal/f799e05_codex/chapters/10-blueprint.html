10. Source를 닫고 재구현·발표하기

학습 목표와 concrete scenario

완전한 Interface/ADT/transition/algorithm/error/recovery contract와 구현 순서를 제시한다.

질문: source를 닫은 채 duplicate residency, use-after-unfix, WAL violation과 lost re-dirty를 어떤 tests로 막을 것인가?

직관: 한 page journey를 identity, ownership, concurrency, durability, release 순서로 따라가며 각 abstraction을 exact state와 guard로 교체한다.

Reimplementation blueprint

  1. Interface: logical PageId, fetch mode, read/write latch, conditionality, explicit borrowed handle/release.
  2. Single-thread: hash, BCB/frame identity generation, hit/miss/load validation, clean unfix.
  3. Concurrency: per-page miss ownership, pin/holder ledger, latch matrix, wait/retry, ordered multi-page acquisition.
  4. Durability: dirty generation, page LSN/oldest LSA, WAL gate, snapshot I/O, error rollback and concurrent re-dirty.
  5. Policy: eligibility predicate before LRU policy, background flush and no-victim progress.
  6. Conformance: duplicate-residency race, use-after-release assertion, conditional failure balance, WAL fault points, re-dirty test.

Glossary and evidence boundaries

VPID
volume/page logical identity.
BCB
resident identity, latch/fcnt, flags, lists, frame를 묶는 control block.
fix / holder
frame replacement을 막는 global accounting과 thread-local nested ownership.
latch
resident page bytes의 short physical consistency; transaction lock과 다르다.
dirty / flushing
resident generation이 storage image보다 새로움 / snapshot I/O가 진행 중임.
victim eligibility / policy
재사용해도 안전한 hard predicate / 후보 중 무엇을 고를지의 heuristic.

Source-confirmed behavior와 관찰 한계

  • 현재 source에는 lock-free READ fast path의 post-CAS VPID recheck가 없다. 외부 재구현 blueprint는 증명되지 않은 최적화를 복제하지 않고 locked fallback 또는 post-CAS backout을 사용한다.
  • DWB read direct return, TDE/DWB-slot early return, async-unfix error clearing은 source-confirmed current behavior다. 재구현은 strict-compatibility와 hardened-rollback 중 mode를 명시한다.
  • Lock-free READ와 normal idle/compatible/blocked grant의 holder allocation 실패는 이미 commit된 latch/fcnt를 backout하지 않는 source-confirmed current behavior다. Hardened blueprint는 holder reserve-first 또는 explicit latch/fcnt rollback을 요구한다.
  • SQL experiments는 actual latch waiter와 victim eviction을 식별하지 않았다. 이는 runtime 관찰 한계이지 lifecycle rule의 미정 상태가 아니다.
  • 대표 heap/B-tree/recovery family를 깊게 추적했으며 모든 transitive call site의 전수 catalog와 performance parity는 선언한 범위 밖이다.

Model / recommended answer key

질문 번호별 방어 가능한 핵심 답
#Model / recommended answer
1VPID-keyed buffer lock이 cold loader를 하나로 직렬화한다. Owner만 provisional BCB를 load·publish하고 waiter는 wake 뒤 hash lookup부터 재시도하므로 duplicate published frame도 막힌다.
2Hit은 residency만 보장한다. Incompatible latch holder가 남으면 unconditional request는 waiter queue와 pgbuf_timed_sleep에 들어가 timeout/interrupt될 수 있다.
3Global fcnt는 모든 successful fix를 세어 frame replacement를 막고, thread holder는 어느 thread의 nested ownership·reentry·dirty history인지를 기록한다. Global만 있으면 caller ownership을 검증 못 하고 holder만 있으면 다른 threads를 합산한 victim safety를 판단 못 한다.
4waiter bit가 새 non-holder READ barging을 막아 queued writer progress를 돕고, 기존 holder reentry는 self-deadlock을 피하려 허용한다. 공정성과 reentrant progress 사이의 의도적 trade-off다.
5Conditional failure는 queue/ownership 없이 즉시 NULL이다. Timed wait는 waiter로 등록된 뒤 timeout/interrupt cleanup과 error code를 거치므로 같은 failure가 아니다.
6Ordered refix는 실제 unfix/refix를 수행할 수 있어 old PAGE_PTR, record pointer, slot과 header-derived state가 stale하다. page_was_unfixed이면 identity와 record lookup을 다시 검증한다.
7Descending sibling 조건부 fix는 반대 방향 latch-order wait를 피한다. Conflict이면 held page를 풀고 ER_DESC_ISCAN_ABORTED로 상위 scan을 재시작해 순환대기 위험을 줄인다.
8Recovery는 allocation/deallocation metadata 자체를 재생 중일 수 있다. RECOVERY_PAGE는 정상 OLD-page 존재 전제를 강제하지 않고 image를 fix할 수 있게 한다.
9DIRTY는 resident image가 data volume보다 새롭다는 뜻, page LSA는 그 image가 포함한 log 상한, oldest-unflush-LSA는 언제부터 flush debt가 생겼는지를 뜻한다.
10Snapshot generation의 old DIRTY를 clear하고 FLUSHING을 set해야 I/O 중 writer가 세운 새 DIRTY를 별도 generation으로 보존할 수 있다.
11일반 write failure는 FLUSHING을 끝내고 pre-flush DIRTY와 oldest-unflush-LSA를 복원해 retry 가능하게 해야 한다. 조기 TDE/DWB 오류는 별도 fault-injection 대상이다.
12DWB는 torn/partial data-page write를 복구하지만, durable log가 없으면 transaction-consistent redo/undo 근거가 없다. 따라서 DWB는 WAL ordering을 대체하지 않는다.
13Flusher가 G를 copy한 뒤 writer가 resident page를 G+1로 수정·re-dirty할 수 있다. G write success 뒤 FLUSHING만 지우고 G+1 DIRTY는 남는다.
14예: LRU1/2처럼 zone3 밖, latch waiter/비-NO_LATCH state, FLUSHING/direct-victim invalid-candidate flag. Avoid-deallocation count는 vacuum deallocation을 막지만 victimization 자체를 막지 않는다.
15Num_data_page_flushed는 특정 victim-candidate flush site의 counter이지 모든 checkpoint write의 합이 아니다. 0은 해당 site 미관찰이지 checkpoint failure 증거가 아니다.
16Clean restart는 최종 복구 가능성만 관찰하며 각 data page 전에 해당 WAL이 durable했는지의 I/O 순서를 보여주지 않는다. 이미 durable한 log와 다른 flush 경로도 대안이다.
17둘 다 replacement protection과 content concurrency를 다루지만 CUBRID는 holder/latch/fcnt를 결합하고 PostgreSQL은 private/shared pin과 content lock을 분리한다. 그래서 partial analogy다.
18InnoDB base row는 clustered index에 있고 MTR memo/latch coupling을 쓴다. CUBRID는 B-tree OID에서 별도 heap page로 handoff하므로 responsibility는 비슷해도 직접 equivalent가 아니다.
19CUBRID는 load+latch 뒤 publish해 waiter가 lookup을 재시도한다. PostgreSQL/InnoDB는 I/O-in-progress mapping을 먼저 publish해 waiter를 같은 frame에 모은다. 전자는 provisional cleanup을 숨기고, 후자는 I/O state와 failure wakeup을 공개한다.
20가장 위험한 unknown은 TDE/DWB 조기 오류가 DIRTY/FLUSHING/oldest-LSA를 남기는 reachability다. 각 callee failure를 inject하고 flags, retry, victim eligibility와 restart invariant를 검사하는 focused test가 최소 다음 단계다.
Final presenter rule. function name을 외우는 것보다 before/guard/action/after/failure/evidence limit를 끊김 없이 말한다. “모른다”는 허용하지만 unknown을 guarantee로 포장하지 않는다.
